# Formal verification — planning basis (M8 seed)

Goal (user directive 2026-07-29): reproduce the review-compression outcome of Lean-verified kernels — a human certifies correctness by reading a small formal spec + running a machine checker; AI-written implementation + proofs stay unread — for this chain's answer computation. Non-binding catalog per the scope guard; M8 planning adopts the minimal subset serving its ledger deliverable. Findings below were web/repo-verified 2026-07-29; sources inline.

## 1 Exemplar case study — verified-3d-mesh-intersection

`github.com/schildep/verified-3d-mesh-intersection` @ `c537025f69511110108acc9608dc1cdb19025057` (MIT; single root commit "initial release"; author P Schilde). All figures re-measured at that pin; `lake build` + the README's axiom/escape-hatch checks were independently rerun in-session (build green, axioms exact, scan empty).

- Review surface = 4 Lean files (data model, geometric semantics, exported kernel contract, canonical diagnostics): 304 physical → 101 nonblank code → 93 after dropping 8 namespace wrappers (the README's "93 lines" = code-only convention; record both counts when citing). Optional `Example.lean` (88 physical) adds anti-vacuity/adequacy theorems (admissible rays exist, unit-cube sanity, solid↔surface bridges) — outside the advertised minimum, material to spec-means-what-you-think confidence.
- Contract = 4 exported theorems: `ok ⇒ solid M = solid M₁ ∩ solid M₂ ∧ WellFormedMesh M`; well-formed inputs ⇒ ok; every error names a genuinely violated precondition; ill-formed ⇒ error. Pattern: extensional object equality + acceptance-completeness + diagnostic honesty + rejection-completeness.
- Unread: impl 4 files / 1,328 SLOC (2,353 physical); proofs 177 files / 73,512 SLOC (97,995 physical; README "60,000+" conservative). Script-enforced AI-caution header on every impl/proof file.
- Certification procedure: `lake exe cache get`; `lake build`; `#print axioms` on the 4 theorems (expect exactly `[propext, Classical.choice, Quot.sound]`); `rg 'implemented_by|extern|csimp|skipKernelTC|unsafe|partial|opaque' CSG/` → no matches.
- Toolchain: `lean-toolchain` = `leanprover/lean4:v4.15.0`; `lake-manifest.json` commit-pins Mathlib + 8 deps (revision pins, no content digests); runtime import closure deliberately Mathlib-free. No CI, manual checks, unsigned single-commit history.
- Process (self-reported; no transcripts published): author controlled only the spec; informal proofs before formalization; mostly Claude Opus 4.8 + some Fable 5 strategy passes; some steps >24 h autonomous; immutable reviewed spec files; sorry-first stubs; `lean-lsp-mcp`.
- Trust story: static implementation-correctness proof, not per-run certificate checking. Human trusts spec adequacy + Lean kernel + pinned toolchain + 3 standard axioms; execution additionally trusts Lean compiler/runtime + glue (`Web.lean` String→String explicitly unproved). The theorem starts at decoded `Mesh` — parsing/serialization outside.
- Cautions: line-count convention ambiguity; deployed TCB > advertised 93 lines; no CI/provenance discipline (this project already exceeds it); huge incohesive proof corpus = acknowledged maintenance debt; unformalized properties (runtime, triangulation quality) stay unguaranteed.

## 2 Transfer analysis — what the same outcome means here

This chain is structurally ahead of the exemplar in one respect: the kernel already emits deterministic, replayable, digest-bound certificates per run. The verified object shifts from a mesh function to answer records over stratified-NAF standard models. Full local inventory (docs/ir.md + fixtures + kernel source, session 2026-07-29):

### Spec-surface baseline (v2, measured)

- Executable program+answer grammar = 26 functor/arity signatures (+7 IR-only = 33 full-chain); ≈30 grouped byte/static-WF rules + 18–22 answer/replay/digest rules.
- Kernel semantics: signed predicate dependency graph; validator rejects all cycles (stronger than stratification) → finite DAG; `σ(p) = max(1, σ(q)[pos], σ(q)+1[NAF])`; per-stratum repeated-pass least fixpoint over clause-entry snapshots; NAF = ground absence in snapshot (= final lower-stratum absence); yes/no = completed-store membership, `not_proved` = unknown; wh = complete extraction, strictly ascending by canonical serialization bytes; `certificate_node_cap(1000000)`.
- Certificates: `proof(GroundAtom, ClauseId, [Sub…])` + positional bare `naf(Atom)` leaves; `not_proved`/`answers([])` carry no certificate. Shipped replay validates witnesses against the unverified kernel's own completed store; it does not recompute saturation or first-witness choice.
- Byte layer = the hidden obstacle to a very small spec: canonical records delegate atom syntax to SWI `write_term` options; an independent checker must formally define the restricted lexical grammar + a proven bytes↔AST decoder, or keep SWI parsing in the TCB. An abstract AST alone does not certify committed bytes.

### Boundary candidates (M8 planning decides)

| id | checker | accept certifies | stays uncertified | est. trusted-spec size |
|---|---|---|---|---|
| B1 | certificate checker over program+result bytes | every proved/listed answer has a valid grounded derivation; NAF leaves positionally correct + absent from an independently established lower-stratum model | `not_proved`/`answers([])`; wh completeness; everything upstream | ~150–250 dense lines |
| B2 | reference evaluator: recompute the standard model from program bytes, compare the complete answer payload | soundness + completeness incl. `not_proved`, `answers([])`, no omitted/duplicate/misordered wh answers | IR→program compilation; upstream | ~180–320 dense lines incl. small byte grammar |
| B3a | IR→program pair checker (4-case structural map; shipped compiler is 57 lines) | supplied program = exact compilation of supplied valid IR → ties B2 verdicts to IR semantics | DRS→IR, ACE | ~30–60 core (+byte grammar shared) |
| B4 | anything upstream of IR (DRS lowering 1,103 hand-Prolog lines, mid-widening; APE parse) | — | ACE/DRS/source faithfulness stays human-audited via ACE text + registry/mapping rows — the charter's auditability thesis, unchanged | out of scope |

Key facts driving the choice: B1 alone cannot certify negative/empty answers or wh completeness (no negative certificates exist), and sound NAF leaves already require lower-stratum model recomputation → B2 subsumes B1's hard part. Composition: `check-model` (B2) + `check-cert` (B1 against the B2-recomputed model) + separable `check-compile` (B3a), sharing one formal decoder/AST/model. Certificates then remain the human explanation channel while the verified verdict covers the full answer relation.

First-witness bytes: denotational spec + any-valid-certificate = smaller trusted surface; exact-first-witness + canonical-byte conformance = separate theorem/checker phase, adopted only if determinism itself is claimed formally. Measure the reviewed surface as the transitive definition/notation dependency closure, not physical lines (short statements can hide large closures).

### Gate: v3 freeze (M6 review)

M6 bumps all three envelopes, regenerates every golden once, and finalizes v3 only at M6 review; it adds labeled NAF leaves, branch IDs, `alternative_set`, quantities/units (canonical rational representation unresolved against the current byte grammar), temporals, direction/hedge annotations → est. +12–20 constructors, +20–35 laws (+40–80% surface). Verifying v2 now = guaranteed migration churn. Safe pre-freeze work: architecture choice, boundary theorem statements, decoder prototype, v2 fixtures as regression vectors. Standing pressure on M6 authoring: every constructor lands in the future trusted spec → keep record/certificate grammars minimal, total, canonical.

### Integration host points (shipped)

CLI `verified-check check-model|check-cert|check-compile`, exit 0/1/2 + zero-stdout/one-diagnostic-line discipline, fresh byte reads, no network. Hosts: `tests/ir-run-harness.sh` (greens + targeted reds; exact-cmp + determinism + digest-tamper patterns already present), `tests/slice-harness.sh` (post-stage), `tests/guideline-harness.sh` (12 production chains), CI job with digest-pinned offline toolchain. Mutation matrix must include the B2 discriminators (omitted valid wh answer; false `not_proved`; false `answers([])`) plus digest/root/clause-ID/child-order/NAF-present tampers and an explicit non-first-witness policy probe.

## 3 Toolchain fit

Lean 4 = primary candidate; verdicts below verified against current docs/releases (2026-07-29).

- State: v4.32.2 (2026-07-28), ~monthly minors, no strong back-compat guarantee → exact pinning mandatory. Linux x86-64 tar.zst 563,991,635 B, SHA-256 `5f2069e6f5db73780f374ccb49ce8ea649aa20a0cebf0116816744c999ce72aa`; self-contained (lean, lake, leanc/clang, leanchecker, CaDiCaL). Apache-2.0 + bundled-component `LICENSES` to preserve on redistribution.
- Vendoring: `lean-toolchain` may name an `elan toolchain link`ed local toolchain → stage the digest-checked archive project-locally (elan itself does not digest-verify downloads), project `ELAN_HOME`, network-denied CI, no `lake update`. `lake-manifest.json` pins revisions, not content digests, and Lake build traces are UInt64 dirtiness hashes → keep this repo's `PROVENANCE` + `MANIFEST.sha256` pattern authoritative on top. Bit-for-bit build reproducibility is undocumented → claim only output-format/theorem determinism until a double-clean-build experiment passes.
- Dependency weight: start core + `Std` only (lists/maps verified against list models; `ByteArray`/`IO.FS.readBinFile` byte-exact IO); Batteries = small escalation (Apache-2.0, zero external deps); Mathlib only if a prototype proves its order/fixpoint library removes more complexity than its footprint adds (its `lfp` is `sInf`-specification, not the needed executable finite saturation). Exemplar precedent: Mathlib for proofs, Mathlib-free runtime closure.
- Trust modes: compiled `lake exe` verdict trusts Lean compiler/C++ runtime/LLVM (Lean FAQ); `decide +kernel` stays kernel-only but can be slow/stuck; `native_decide` admits a per-invocation compiler-trust axiom (auditable since 4.29). Preferred posture: soundness theorem about the pure checker on exact input bytes; compiled runner for normal use; a compiler-independent certification mode (closed kernel check / exported proof) for the assurance claim; `leanchecker --fresh` every build (kernel replay, not independent); `comparator` = strongest precedent for unreviewed AI proofs (sandboxed export, statement comparison vs trusted challenge, axiom allow-list, optional `nanoda` second checker); Lean4Lean = useful diversity, self-declared incomplete.
- Gates to ship: zero `sorry`; `#print axioms` regression guard (`#guard_msgs`; target axiom-free or exactly the standard trio); escape-hatch scan over the pure checker's transitive cone; raw-printed trusted spec module compared declaration-wise.
- Automation an AI prover leans on: `simp`/`omega`/`decide`/`grind` (proof-term-producing, zero extra deps) + optional pinned Aesop/Duper/lean-auto (native route only; SMT/TPTP oracles lack reconstruction).
- AI-scale precedents (author/paper claims, dates verified): the exemplar (73K proof SLOC); M2F arXiv:2602.17016 (153,853 lines / 479 textbook pages / ~3 weeks); AutoformBot/Atlas arXiv:2605.29955 (>500K lines, 26 textbooks); Vlasov–Maxwell–Landau arXiv:2603.15929 (10 days, $200, human reviewed only definitions/statements; failure modes: hypothesis creep, definition misalignment). Feasibility of proofs ≫ impl size: credible; volume/repair cost: unpredictable.
- Alternatives ranking for this use: 1 Lean 4 (balance: small reviewed spec, current AI ecosystem, ordinary proof replay, single self-contained toolchain); 2 CakeML v3400 (BSD-3; verified compiler to machine code; best if the verdict must rest on a verified native binary; HOL4 proof authoring + heavy source rebuild ~64 GB RAM) — the benchmark comparison prototype; 3 Rocq 9.2.0 (LGPL-2.1 core; mature; extraction + OCaml runtime trusted; opam lock/cache offline staging) — strongest conventional fallback; 4 Isabelle2025-2 (+AFP; standard code generator's translation/serialization trusted unless paired with the verified HOL→CakeML route); 5 ACL2 8.7 (natural first-order executable logic; weaker TCB separation; 8.7 notes record old soundness-bug fixes); 6 F*/Why3 (Z3 verdicts without checked certificates / VC orchestrator — misaligned with a tiny machine-checked TCB).

## 4 Prior art — certifying logic-program answers

- Closest single precedent: **DatalogCert** — Benzaken, Contejean, Dumbrava, "Certifying Standard and Stratified Datalog Inference Engines in SSReflect", ITP 2017, DOI 10.1007/978-3-319-66107-0_12 (dblp-verified). Coq/SSReflect mechanization of Datalog semantics with certified engines for both standard (positive least-fixpoint) and stratified evaluation — the same semantic family as this chain (finite, function-free, stratified NAF). Existence proof that the semantics + certified-engine package fits a proof assistant at modest scale.
- Methodology frame: **certifying algorithms** — McConnell, Mehlhorn, Näher, Schweitzer, Computer Science Review 2011 (author-copy PDF byte-verified: output + witness + simple checker; user trusts the checker, never the algorithm). Mechanized instance: Alkassar, Böhme, Mehlhorn, Rizkallah, "A Framework for the Verification of Certifying Computations", arXiv:1301.7462 (CAV 2011 preliminary): checker-code correctness (VCC) + witness-property soundness (Isabelle/HOL). B1/B2 instantiate exactly this pattern: untrusted Prolog kernel emits witnesses/records, a verified checker validates them.
- Verified certificate-checker deployments at scale = §3's Lean LRAT `check`+`check_sound`, PBLean, and CakeML's application family of end-to-end verified proof checkers — evidence the reflective checker+soundness-theorem architecture is production-real in SAT/PB; this project transplants it to stratified-Datalog answer records.
- ASP: **anthem** (potassco, MIT, active v2) translates mini-gringo ASP into many-sorted first-order theories and discharges strong/external-equivalence obligations via external ATPs — an unverified translator over untrusted provers, not a small-TCB checker. Relevant only if a future D1-trigger deviation adopts ASP-class semantics; no verified ASP answer checker surfaced in this sweep.
- Coverage note: sweep truncated by tooling outages (dblp publication search partially down, AFP search client-rendered, session search budget exhausted); Lean-4-native Datalog/LP formalizations unverified this session. M8 planning re-sweeps (AFP logic-programming entries, later Coq Datalog work incl. provenance/differential lines) before the final architecture choice; plausible-but-unverified leads are omitted here rather than cited.

## 5 Recommended target (candidate — M8 planning finalizes)

One Lean 4 package (e.g. `verify/`): reviewed spec module (v3 record byte grammar + decoder relation + stratified standard-model semantics + contract theorem statements + a few adequacy examples; target ≤ ~300 dense lines with the dependency closure reported) + unread AI-written pure checker (byte parser, reference evaluator, certificate replayer) + unread proofs + `lake exe` runner over committed program/result bytes. Contract mirrors the exemplar's 4-way shape lifted to records: accept ⇒ complete answer relation holds + every certificate valid; valid v3 artifacts ⇒ accept; diagnostics honest; invalid ⇒ reject. Human procedure: read the spec module, `lake build`, axiom guard, escape-hatch scan, run the checker across the corpus via the harnesses. Result: the Prolog kernel/compiler leave the trusted base for answer correctness; ACE→IR meaning stays human-audited (ACE + registry/mapping) exactly as chartered.

Open questions for M8 planning: v3-final grammar actually frozen (gate); checker-facing concrete syntax = reuse canonical Prolog-term bytes vs add a simpler checker-oriented encoding at generation time (would shrink the byte-grammar spec; changes pipeline outputs → decide before authoring the spec); SHA-256 digest binding inside vs outside the theorem (hashing spec cost); first-witness conformance phase adopted or explicitly waived; kernel-mode certification cost on corpus-scale certificates (measure; PBLean scale reference: ~63K-line certificate ≈ 200 s reflective); Lean pin cadence policy under monthly releases; double-build byte-determinism experiment; prototype before committing (bounded: v2-fixture decoder + evaluator + soundness skeleton on core+Std, measuring spec closure, proof LOC, check times, clean-build byte equality).
