- Access probing = evidence, and silence is not evidence. A 2xx describes the REQUEST, never the artifact, in two shapes: zero bytes → `empty(<code>)`, and a cookie/session interstitial → `challenge(cookie-wall)`. Atypon and Silverchair (JACC, `pubs.asahq.org`, `journals.lww.com`, JCSM, Wiley, `jospt.org`, `liebertpub.com`) answer a cookie-less fetch with 200 + real HTML + no artifact bytes at `/action/cookieAbsent`, so a body-only test scored 88 of 96 ACC probes `open` — a FALSE open, strictly worse than a false negative because the row then promotes and the fetch cannot succeed. The FINAL url is what separates them (`/action/(cookieAbsent|cookieSet|showLogin)`, `[?&]cookieSet=`); routing through `challenge(...)` keeps the reader rescue reachable, so a proxy retrieving genuine bytes still earns `open(reader)`. Probe evidence predating a prober fix is void for every redirected URL — re-probe rather than reason about which lines survive.
- Split probing from adjudication across the wave: probing is per-host serialised and mechanical, adjudication is neither, so a producer's window buys far more sitting on eligibility. Producers emit every eligible row `unverified` + `provisional(access probe pending)`; MAIN runs one prober pass per report and promotes cells with `.scratch/apply_probe_access.py`, which is convergent (rewrites only where evidence disagrees, so re-probing just the pending rows suffices) and refuses to decide `gated(...)`, since `paywalled(<gate>)` vs `login(<gate>)` names which gate the body showed. Probing is what saturated four of six M1.2b producers; the two that skipped it finished a full org in a third of a window.
- Naming an issuer is a claim about the ARTIFACT; `CPGs` is a claim about the ORG's enumeration evidence. Requiring every org-cell part to read `CPGs=yes` inverted that dependency and made co-issued work unrecordable — ACC's 161 entries alone name 61 society acronyms, 16 of them `yes`, and across the M1.2b wave 73 distinct issuers over 447 rows would have failed. The predicate is instead: every part holds an org row, and none reads `CPGs=no` (a positive finding that the org issues nothing eligible, so a row naming it is a contradiction). A sweep still never widens the universe; `.scratch/fix_m1u2b_new_issuers.py` materialises the missing rows `unverified`/`swept=pending` after the merge, which turns M1.3's worklist into table rows instead of prose. Issuer hosts answer a burst with throttle shapes indistinguishable from refusals, so an unpaced sweep manufactures its own inaccessibility: `www.healthquality.va.gov` drops connections; `www.cdc.gov` 403s. All clear on a paced re-probe. A throttle shape is a hypothesis until the mechanism is read: `library.samhsa.gov`'s 202 + zero bytes is NOT metering and no cooldown clears it — send browser headers and the same 202 carries 2,423 bytes of `awsWafCookieDomainList`/`gokuProps`, and a real browser gets `Let's confirm you are human` escalating to an image CAPTCHA. The guard is path-scoped to `/sites/default/files`; product pages and `/search-endpoint` answer normally, which is what distinguishes an anti-bot gate (needs a human) from a budget (needs waiting). `probe_urls.py` therefore serializes per host behind a lock held across the sleep + retries transient shapes; `probe_until_settled.py` grinds a metered host across cooldowns so each row earns its own verdict. Treat a whole-host `open` generalisation as unproven. Refinements for M2: a 202 + 0 bytes means CHALLENGED, never dead — deadness reads as `Page Not Found` HTML through a browser that has cleared the check. The guard is path- and cache-scoped rather than host-scoped, so try case variants before ruling a URL dead: `PEP20-02-01-022.pdf` serves anonymously (200, 427,172 B, `%PDF-`) while the same path lowercased 202s. `/search-endpoint` is a probe, not an enumerator — it returns page 1 of all 754 products and ignores every query + pagination parameter over GET and POST alike. Delisted TIPs live on NCBI Bookshelf (TIP 42 `NBK571020`, TIP 61 `NBK539583`), already the compendium's host for TIP 39 + TIP 51. The image CAPTCHA refuses scripted tile clicks — each `click_at` advances to a fresh challenge instead of selecting — so clearing it needs the user, once per host. Once cleared, read the artifact by evaluating a same-origin `fetch()` in an already-open page on that host (`mcp__browseros__evaluate`, returning status + `byteLength` + magic bytes): the clearance lives in the browser's cookie jar, so `curl` keeps answering 403 while the page context serves full bytes. That route verifies an artifact at byte level without downloading it, and generalises to every challenge-gated issuer.
- Row re-verification reads the artifact's own text: `pdftotext -l 8` on a PDF, tag-stripped HTML otherwise, `r.jina.ai` only where a direct fetch is refused. A throttled reader returns a ~200-400 byte stub whose `Title:` header echoes the document, so title matching on a stub confirms itself — anything under ~2000 bytes verifies nothing and must be reported `thin`, never clean. `jts.health.mil` PDFs render as stubs through the reader but extract fully via `pdftotext`.
- Sweep manifest vs table: a co-issued guideline may sit in every issuer's index or in only one, and the merged table records issuers but never which index surfaced the row, so no post-merge predicate can decide manifest truth — an interval over the table (`sole <= claimed <= counting_co_issued`) accepts both an org counting a joint row its index omitted and the co-issuer dropping the row its index carried. The reports still hold that provenance, so `merge_rows.py` checks it pre-merge: manifest `<e>/<x>` == the rows that org's own report block emits. Exact while co-issuers are swept by SEPARATE reports (the real `ACIP + HICPAC` case); one report sweeping both counts the joint row for each, so split co-issuers across reports wherever a manifest must be provable. When BOTH issuers' indexes carry the co-issued artifact (ACIP's smallpox topic page and HICPAC's index both list rr5207a1), both reports emit the row byte-identically and both manifests count it — the merge deduplicates to one table row and refuses on any cell disagreement, decided BEFORE lifecycle suppression so a `queued|in-progress|done` row cannot hide a disagreement until it clears. A silent report would instead show `n - (e + x) > 0` and read as a collapse it never made. Exactness rests on the report being the row's provenance, so one report sweeping every issuer of a co-issued row is refused: it records no finer origin than the batch. `indexed-by=<org>[ + <org>...]` names the whole set of carrying indexes (naming exactly the issuers = the default, refused as redundant), which is how an artifact its issuers and a third org all index counts once in each manifest. The two provenance markers answer one question → a row carries at most one, and never two `indexed-by=`. An `off-index(...)` row belongs to no manifest and no index sweep retracts it — silence from an index is not evidence about a row that was never in one — so only a batch re-emitting the artifact (matched on URL or issuers+title) replaces it.

- An org's guideline index = the BROADEST listing on its own site that enumerates its clinical-guidance artifacts and still enumerates inside the easy tier. A narrower filtered view is not sweepable while a broader own-site listing exists: the header emits no row for material outside the swept index, so sweeping the narrow view records the org as swept while its other eligible artifacts hold neither a row nor a deferral. Where the broad listing outruns the tier, the whole org takes `blocked(<why>)` — deferral is honest, silent narrowing is not. Societies publish one corpus under many labels, and the recorded index often sees a fraction: ACOG's own Coveo endpoint (`POST https://www.acog.org/coveo/rest/search/v2`, anonymous, `groupBy` on `@selectedcontenttype`) counts ~2,500 clinical records across 11 guidance types against the 61 the compendium's `Clinical Practice Guideline` facet carries.
- `merge_rows.py`: an issuer's sweep may REPLACE a co-issued row its own index carried, printing the diff for a MAIN ruling. Tiering splits co-issuers across milestones (ACC in M1.2b, AHA/ADA/ASN in M2), so "sweep every issuer together to replace it" is unreachable and would freeze a co-issued row at its seed-era cells forever. Replacement authority = ownership: one of the row's issuers, or the index that carried it (`claim_orgs(row) & (issuers(stale) | attrib(stale))`), OR an emission naming every issuer the retained row named. That superset clause is what lets a third index improve a row it shares no issuer with — AASM's Endorsed Guidelines subindex carries the benzodiazepine guideline whose seed named ASAM alone, and the sweep emits all eleven issuers plus `indexed-by=` — while an emission that DROPS an issuer stays refused as a competing claim about authorship rather than a better-attributed row. A `queued|in-progress|done` row is suppressed rather than replaced, co-issued ones included.

- MMWR states a recommendation's label year in the title (`— United States, 2024`) and its publication year in the volume (`year = 1951 + volume`, readable from every URL shape), and the two differ constantly. Rows record `title (label-year; pub YYYY)` whenever they differ, since the table sorts on version year; a season range (`2024–2025`) names no single label year and keeps the publication year alone, and a month may sit between the scope clause and the label year (`— United States, December 2024`). The volume rule holds across all 75 shipped MMWR rows with one exception in the shape it predicts: a late issue cover-dated into the next January (56(51) → January 4, 2008) takes the date's year. - A guideline that consolidates another body's recommendations without adding new ones stays eligible: it carries systematically developed patient-care recommendations, which is the test — `does not contain any new recommendations` describes novelty, not content. A manifest reconciles an INDEX while the org cell records ISSUANCE, so the two diverge routinely; notes carry `indexed-by=<org>` (counts in the indexer's manifest, issuer keeps the org cell) or `off-index(<why>)` (no index carried it, so no manifest counts it — the shape the cross-check's gap rows need).
