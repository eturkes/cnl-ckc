- Access probing = evidence, and silence is not evidence. A 2xx carrying zero bytes describes the request, never the artifact → verdict `empty(<code>)`, never `open`. Issuer hosts answer a burst with throttle shapes indistinguishable from refusals, so an unpaced sweep manufactures its own inaccessibility: `library.samhsa.gov` returns 202 + zero bytes (its site root throttles alongside the artifacts, which is how the shape is known to be metering) and meters a slowly-refilling per-IP budget that pacing alone cannot buy past — only waiting; `www.healthquality.va.gov` drops connections; `www.cdc.gov` 403s. All clear on a paced re-probe. `probe_urls.py` therefore serializes per host behind a lock held across the sleep + retries transient shapes; `probe_until_settled.py` grinds a metered host across cooldowns so each row earns its own verdict. Treat a whole-host `open` generalisation as unproven.
- Row re-verification reads the artifact's own text: `pdftotext -l 8` on a PDF, tag-stripped HTML otherwise, `r.jina.ai` only where a direct fetch is refused. A throttled reader returns a ~200-400 byte stub whose `Title:` header echoes the document, so title matching on a stub confirms itself — anything under ~2000 bytes verifies nothing and must be reported `thin`, never clean. `jts.health.mil` PDFs render as stubs through the reader but extract fully via `pdftotext`.
- Sweep manifest vs table: a co-issued guideline may sit in every issuer's index or in only one, and the merged table records issuers but never which index surfaced the row, so no post-merge predicate can decide manifest truth — an interval over the table (`sole <= claimed <= counting_co_issued`) accepts both an org counting a joint row its index omitted and the co-issuer dropping the row its index carried. The reports still hold that provenance, so `merge_rows.py` checks it pre-merge: manifest `<e>/<x>` == the rows that org's own report block emits. Exact while co-issuers are swept by SEPARATE reports (the real `ACIP + HICPAC` case); one report sweeping both counts the joint row for each, so split co-issuers across reports wherever a manifest must be provable. When BOTH issuers' indexes carry the co-issued artifact (ACIP's smallpox topic page and HICPAC's index both list rr5207a1), both reports emit the row byte-identically and both manifests count it — the merge deduplicates to one table row and refuses on any cell disagreement, decided BEFORE lifecycle suppression so a `queued|in-progress|done` row cannot hide a disagreement until it clears. A silent report would instead show `n - (e + x) > 0` and read as a collapse it never made. Exactness rests on the report being the row's provenance, so one report sweeping every issuer of a co-issued row is refused: it records no finer origin than the batch. `indexed-by=<org>[ + <org>...]` names the whole set of carrying indexes (naming exactly the issuers = the default, refused as redundant), which is how an artifact its issuers and a third org all index counts once in each manifest. The two provenance markers answer one question → a row carries at most one, and never two `indexed-by=`. An `off-index(...)` row belongs to no manifest and no index sweep retracts it — silence from an index is not evidence about a row that was never in one — so only a batch re-emitting the artifact (matched on URL or issuers+title) replaces it.
- A gate test that re-runs the tool's own detection regex over the shipped corpus proves nothing: replace the regex with `(?!)` and it stays green, because a detector that finds nothing reports nothing wrong. Drive the TOOL over synthetic positives and negatives instead, and keep the corpus scan as a separate convergence check pinned to the shipped tool (never to `M1U2A_ARTIFACT_DIR`, which swaps tool variants). Mutation is the measure: `.scratch/m1u2c/rev2-1/run_mutants.py` regenerates one-behavior mutants of the attribution predicates from `base/` (refresh it from the live tools first) and scores them against the gate.

- Repair-script idempotence keys on a field's SHAPE, never its exact current text. `fix_m1u2a_samhsa_access.py` admitted a row only when `status` equalled the one string today's `why()` builds, so rows an earlier version wrote against a different host matched nothing, were skipped, and could never be promoted however much evidence landed — two artifacts sat `unverified` blaming a host they are not served from while their own `open` probes sat in the evidence file. - Access probing serializes per host across the REQUEST, not just its start: holding the lock only over the sleep spaces request starts while slow same-host fetches overlap (measured 4 concurrent), which is the concurrency a meter counts. `probe_urls.py` holds the lock across `urlopen` and measures the gap from completion → idle time the host observes.
- ACIP's vaccine-specific index enumerates 27 TOPIC pages, each a subindex whose `CURRENT` section lists several scope-distinct artifacts (Rabies: 2022 PrEP + 2010 4-dose PEP + 2008 baseline, `ARCHIVED` empty) — 67 CURRENT listings = 66 distinct artifacts, against 27 rows for one-row-per-topic. A bounded fan-out is easy tier (compendium header owns the clause): enumerable from the index in one fetch, ≤30 subindexes, each anonymous + static ⇒ `1 + <subindexes>` fetches, method `per-topic-pages`. No aggregate endpoint substitutes: `recs-by-date` stops at 2024 and mixes current with superseded, and one of its rows links the wrong artifact. Parsing a topic page has three traps, each worth one artifact: `Archived DTaP-IPV-Hib-HepB …` capitalizes ARCHIVED differently from every other page, a listing links its own article with a tracking query (`mm7336a4.htm?s_cid=…`), and one listing may link several articles whose extras are its `Print version` and `Appendix` — parts of an artifact, not artifacts. `mm7336a4` is listed under two topics, so raw listings exceed distinct artifacts.
- MMWR states a recommendation's label year in the title (`— United States, 2024`) and its publication year in the volume (`year = 1951 + volume`, readable from every URL shape), and the two differ constantly. Rows record `title (label-year; pub YYYY)` whenever they differ, since the table sorts on version year; a season range (`2024–2025`) names no single label year and keeps the publication year alone, and a month may sit between the scope clause and the label year (`— United States, December 2024`). The volume rule holds across all 75 shipped MMWR rows with one exception in the shape it predicts: a late issue cover-dated into the next January (56(51) → January 4, 2008) takes the date's year. Titles come from the artifact's own `Suggested citation for this article` line — a topic page's link text is display shorthand, and three ACIP rows shipped it. Two current artifacts stay scope-distinct when the later replaced one component of the earlier (mm7349a3 vs rr6909a1's MenB-4C schedules); the earlier row's notes carry the version qualifier, quoted from the superseding artifact.
- A guideline that consolidates another body's recommendations without adding new ones stays eligible: it carries systematically developed patient-care recommendations, which is the test — `does not contain any new recommendations` describes novelty, not content. Check the ISSUER cell instead, since such artifacts are commonly indexed by a body that only reviewed them (HICPAC indexes MMWR rr6007, whose work group, vote and title are ACIP's). A manifest reconciles an INDEX while the org cell records ISSUANCE, so the two diverge routinely; notes carry `indexed-by=<org>` (counts in the indexer's manifest, issuer keeps the org cell) or `off-index(<why>)` (no index carried it, so no manifest counts it — the shape M1.4's cross-check gap rows need). Sweep tooling attributes deletion, claiming and counting by the same rule.

- Compendium mutation tooling: `.scratch/merge_rows.py` = the only M1.2+ row inserter and the canonical full sort (orgs class→CPGs→alpha; guidelines open-band→class→org→year desc→title). A sweep is total for its org — every guideline row of an org whose emitted `swept` is a date is deleted, then the report's rows insert, so the sweep and not the seed defines that org's rows; `blocked(...)` deletes nothing; `queued|in-progress|done` rows outrank a sweep, are kept verbatim, and their suppressed corrections print for a MAIN ruling. Reports are the source of truth → repair a report and re-merge, never hand-edit the compendium; every repair lands as an idempotent script so the wave stays re-derivable. `.scratch/apply_fixes.py` + `.scratch/splice_compendium.py` = M1.1-only; they reject sweep/provisional states and erase harvest → never reuse for M1.2 rows.
