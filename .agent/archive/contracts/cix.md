## Design

D1 Class (kernel ghost spec): `class(t)` = `Atom(name)` for an atom, `Comp(name, arity)` for a compound, none for a variable, an integer or `[]`. Head class of a clause = the class of its head's first argument; none for a non-compound head (it never matches: `lit_fa` is none). Integers + `[]` stay classless: classless heads join every candidate set (conservative inclusion, never omission).

D2 Candidate (kernel ghost spec): clause j is a candidate for the selected goal `Comp(name, args)` iff `lit_fa(db[j].head) == Some((name, |args|))` and (class(args[0]) none ∨ head class none ∨ head class == class(args[0])), the goal's arguments as they stand when the goal is selected. A non-candidate with a matching predicate has nonempty arguments and two present, distinct classes ⇒ a rigid clash of the first pair (atom ≠ atom, atom vs compound, compounds of different name or arity), kept under renaming (`clash_under_shift`), so the spec's `unify` on `call`'s exact `UState` (any continuation + solution) is `Fail` (`clash_fails`), never `Out`.

D3 Index (kernel exec `EClauseIndex`, built over a clause sequence B, owned data only: names, arities, classes, positions): per predicate (name, arity) with ≥ 1 compound head: `all` (every clause of the predicate), `wild` (head class none) and one list per head class; each list strictly increasing and exact (j ∈ list ⟺ j < |B| ∧ the list's property holds of B[j]); coverage: every compound head has its predicate's entry, every classed clause its class list.

D4 Lookup `next_candidate(from)` over db with `index_valid(ix, db, front)` = (front ≤ |db| ∧ ix exact over db.skip(front)): from ≥ |db| → none; else the least candidate j ≥ from = the first candidate in [from, front) by a direct scan in db order, else front + the inclusive lower bound at max(from, front) − front of `all` (classless goal, incl. no argument) or the smaller of the lower bounds in the goal class's list and `wild` (a missing class = `wild` alone; a missing predicate = none). Proof obligation: every index skipped between from and the result is a predicate mismatch or a D2 clash ⇒ spec `call(from) == call(result)`; no candidate ≥ from ⇒ spec `call(from) == fail(c)`. `call` keeps `head_clash`, renaming, occurs-check `unify` and `enter_clause` after the lookup; the entered clause keeps its original db index m (its choicepoint resumes at m + 1).

D5 Threading + lifecycle: K2 `call` (front-goal dispatch and `step_selected`'s in-place call), `step`, `step_selected`, `run_inner`, `run` take `(ix, front)` + `index_valid`. Validity is a property of the db view alone (no arena reference), so it holds through every arena change that keeps the db view: growth, `run_inner`'s truncation to marks and floor, `finish`, `head_proved`'s truncation. `solve` keeps its signature (answers: builds one index over the composition per query, front 0) beside an indexed form; `head_proved` + `heads_proved` call the indexed form, never the building wrapper; the aggregate replay (`k2_aggregate` `first_unproved_exec` / `unproved_inner`) builds one immutable index over the composition that spans every obligation + head, and proves each obligation over its witness db `reverse(facts).map(fact_clause) ++ composition` at front = the fact count (`witness_db(facts, db).skip(|facts|) == db`), the prefix scanned in its actual order. Every ensures stays the spec refinement it is today (`step_view == spec step`, `run`, `solve`, `head_proved`, `heads_proved`, `first_unproved`). K3 (traces, its own `call`) and recursion-check keep their scans; the linear `next_match` stays for K3.

D6 Bounds + order unchanged: transitions, depth, fuel, choicepoint order, eso selection, CS0 frames and every answer, trace, verdict and reject byte stay equal; only time changes.

## Predicates (acceptance)

- P1 timing (seed-red): `.agent/archive/bench/cix-aggregate <repo-root> <base-bin> <unit-bin> [rounds]` (committed, root-parameterized): regenerates both manifests from the given tree (fork proof payloads through a stage of the tree's `vendor/ape` + Clex; pre-guard = the tree's table minus its `scope` + `exclusion` rows, pl recompiled; guarded = the tree's committed pl), records sha256 of both binaries + every input manifest, then runs a predeclared schedule: 5 rounds × 4 runs, order base-pre, unit-guarded, base-guarded, unit-pre (reversed in even rounds), each `ckc v1 aggregate-check` under `/usr/bin/time` with the 1-minute load before + after; metric = user + system CPU seconds; prints every raw run + the medians; rc 2 when payload regeneration fails; rc 1 when any timed run exits nonzero, when the first base report on a manifest is no `ok` report, when any report differs from it, or when median(unit-guarded) > 2 × median(base-pre); rc 0 = pass. Grading input = the unit's merge-base tree (frozen). Uncontended = no other `heavy` holder and 1-minute load < 2 at every run start: one block decides; contended: two complete blocks, both must pass, and a disagreement = inconclusive (no pass); the commit body records holders + loads either way. Seed-red = the same command with unit-bin = base-bin → rc 1.
- P2 identity: `ckc check` verdicts + meters on the corpus unchanged; `just check` leaves `guidelines/` byte-identical; every committed `tests/v1`, `tests/queries`, eso, cs0, cs1, nt1, root-exact and certify pin unchanged (no existing pin changes); both P1 manifests' aggregate reports byte-identical to the base binary's.
- P3 differential (diff-blind tester), two lanes:
  - (a) CLI lane (`rust/ckc/tests/cix_cli.rs` over `tests/cix/`): admissible compositions only (the codec admits the 18 semantic predicates at their fixed arities) — heads whose first argument is a variable, an integer, `[]`, an atom, compounds of different names + arities; a predicate's clauses interleaved with others; goals of each first-argument kind incl. a class no head has; several solutions spread across class + `wild` lists; redo after a head clash and after a unification failure (occurs check, equal outer classes); negation + eso waiting goals; aggregate witness facts of the goal's predicate (matching, clashing, classless) before the composition, with an order-sensitive witness case — `ckc v1 answer`, `ckc v1 trace` + `ckc v1 aggregate-check` stdout, stderr + rc byte-identical to pins the base binary generated (binary = `just build` of `archive/cix-base`).
  - (b) direct-kernel lane (`#[cfg(test)]` module in `ckc-kernel`, over the seed API `k2_index::{build_index, next_candidate}`, the `k2_term` `push_*` constructors and `k2_engine::solve`): an independent linear candidate oracle (D2 evaluated at every original index, first j ≥ from) over the general domain — every from in 0..=|db| + 1, every front in 0..=|db|, empty db / prefix / suffix, a missing predicate or class, one name at two arities, non-compound heads, variable + `[]` wild heads, class/wild interleaving, duplicate heads; plus raw `solve` rows in order, with duplicates + the complete flag, under small fuel + depth cuts, pinned from the seed engine.
- P4 `just verify` 0 errors 0 warnings with every theorem kept; `ckc-spec` + the spec manifest byte-identical; `just gate` green.
