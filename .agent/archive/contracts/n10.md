# N10 — `just outdated` reports semver-held crates as `held` (contract; user-approved; archived at unit close)

Row = queue-run find, opened + closed in the N10 commit (user ruling, AskUserQuestion: "bump every release" + `held` status in this run). Find: `just outdated` counts a crate as drift whenever crates.io has a newer stable version, including versions the locked graph's requirements exclude; at 67fcdcd0 three such crates (convert_case 0.12.0, syn 3.0.8, synstructure 0.14.0: `verus_builtin_macros` requires `^0.4`, `^2.0`, `^0.13.2`) keep the weekly `updates` job red with no bump available.

## Design

- D1 fixable = the locked (name, version) rows `cargo update --dry-run --manifest-path <ws>/Cargo.toml` would change, per workspace (`rust/`, `rust/ckc-kani-harness/`), run from cwd `/` with an empty `CARGO_HOME` (neither the vendored-source config nor a user config applies) under `RUSTUP_TOOLCHAIN` = `verus.lock` `rustc_toolchain`: `Updating|Downgrading <name> v<cur> -> v<new>` → `to <new>`; `Removing <name> v<cur>` (consolidated into another locked version) → `removed` (R1).
- D2 crate row: current = latest → `ok`; (name, current) fixable → `drift` + its D1 detail; else → `held` + `by <its direct dependents>` (an unqualified lock entry names that crate's one version in its own lock). Verus family rows keep `follows verus`; tool, verus + kani rows unchanged.
- D3 rc: 2 = any error (an empty upstream answer, a failed upstream request, or a failed dry run with its output on stderr); 1 = any `drift`; 0 otherwise (`held` never reds). Summary `outdated: <pins> pins, <d> drift, <h> held, <e> errors`. `CKC_OUTDATED_ROOT` = a tree holding `rust/` (locks + manifests).
- D4 Verus pace (user ruling): every stable Verus release = a bump (`verus` drift stays actionable).
