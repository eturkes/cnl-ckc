## Design

D1 Table rows (spec `vocabulary.rs`, fork `v2_row`, kernel mirror). Two kinds; for both, field 2 names a document or a passage, not a lemma:
- `supersession	<docid>	<date> <url> <citation>`: every sentence of document `<docid>` is superseded from `<date>` by the source at `<url>`, cited as `<citation>`.
- `superseded	<region>	<date> <url> <citation>`: the passage `<region>`, which has no document of its own (uncovered or restating), is superseded likewise; no compile effect (the guideline README + SUP4's page table read it).
Field-2 law: `supersession` = the docid grammar (`name_ok`), else `supersession document`; `superseded` = `lemma_ok`, else `lemma` (the generic law, unchanged).
Value law (both kinds, else `supersession value`): `<date>` = 8 ASCII digits YYYYMMDD naming a proleptic Gregorian date with ISO 8601 four-digit years 0000–9999 (month 01–12; day 01 to the month's length; February has 29 days when the year is divisible by 4 and not by 100, or by 400, so 0000 is a leap year), then one space, then the url token = the bytes up to the next space = `https://` followed by ≥ 1 bytes in 0x21–0x7E, then one space, then `<citation>` = the rest, ≥ 1 bytes of valid UTF-8, none < 0x20 or = 0x7F, first and last byte not a space. The url token ends at the first space after the date, so a url spells a space as `%20`; `<date> https://a b C` parses as url `https://a`, citation `b C`.
Duplicates: a docid in at most one `supersession` row (`duplicate supersession`), a region in at most one `superseded` row (`duplicate superseded`); the later row reports. Row check order unchanged: comment, fields, lemma, kind, value, duplicates; pairing last.
Corpus law (`ckc check`, guideline tables `guidelines/<id>/vocabulary.tsv` only, after the coverage ledger parses; spec `check.rs`, kernel mirror): a `supersession` docid has the coverage row `ace(<docid>)`, else `ckc: supersession: <path>: supersession document at row <n>`; a `superseded` region is a coverage region whose status is not `ace(…)`, else `… superseded region at row <n>` (unknown region and an `ace` region alike). Fixture tables (other paths) skip it; the UI intake parses the kinds through the shared grammar (no refusal for an unknown docid; SUP4 renders only matches).

D2 Record (indicator `guideline_supersession/4`, after `guideline_exclusion/1`): in a document compiled with a table holding a `supersession` row for its docid, every sentence bundle ends with one ground fact `guideline_supersession(DocId, S, source(Citation, Url), Date)` — S = the bundle's sentence ordinal, Citation + Url = atoms holding the row's text, Date = the integer YYYYMMDD. It stands after every other clause of its bundle (an exclusion record included), outside every group: no obligation, no witness, no payload term, no `'$guideline_id'` subterm (coverage identities unchanged). A document without a row emits none.

D3 Evaluation date (indicator `guideline_evaluation_date/1`, after `guideline_supersession/4`): consumer data `guideline_evaluation_date(Date)`, the date for which a consumer evaluates its composition. Consumer precondition (stated in REFERENCE, not checked by the KB): one fact per composition (as one patient: cs1 D5), Date = a valid YYYYMMDD integer. The KB compares numbers alone (`guideline_satisfies/4`): any number below the effective date unblocks — a rational, 0, a malformed integer such as 20220230 included — a non-number blocks, and with several date facts one below the effective date unblocks (an existential test). No compiled clause heads it; documents declare it, so any composition co-loads with the consumer's fact; only the D4 guard reads it.

D4 Guard (block by default; ex nunc): in a superseded document, every group whose clauses include a `deontic_edge` head (`guideline_operator(_, _, should|must|may)`, any depth: a should under `can` or under `-` counts) gains, on every clause of that group, the two body goals `guideline_evaluation_date(V), guideline_satisfies(exactly, V, less, Date)` — V a variable that no clause of the group holds, Date the row's integer — placed after every other body goal, except that a clause carrying the cs1 scope guard keeps that guard last (the two goals stand right before it: cs1 D5 unchanged). The group's witness pairs gain V ↦ Date − 1, a numeric replay witness: an integer below Date, under which the comparison holds, not always a calendar date (20230101 − 1 = 20230100); its obligation's facts gain `guideline_evaluation_date(Date − 1)` (the first clause's positive goals; built-ins excluded as today). Groups without a deontic edge (asserted rules, `can`-only claims, facts) and every unsuperseded document stay byte-identical. Semantics: the guard adds an earlier evaluation date as a necessary condition of a superseded document's should|must|may variants; their original conditions and the cs1 scope guard still apply. With no date, or only dates on or after the effective date, they never derive; the records derive in every composition. A rule of another document that reads a blocked variant's content stops deriving with it (intended: the block removes the superseded statement's content from every derivation that uses it); a document that reads no superseded variant keeps its bytes and its answers. Guarding whole variants (not only edge clauses, cf. cs1) keeps the variant's one shared body and blocks the statement's payload with its edge; no negation enters (the guard is positive), so no stratification or loop argument is needed.

D5 Rejects (class `unsupported`, `supersession_shape(Why, S)`, superseded documents only; each sentence's check runs after its existing translation, the duplicate-grade check and the scope pass, so every existing reject reports first — in a scoped document `scope_shape(root_deontic, S)` reports before it): `root_deontic` — a root (fact) sentence holding a should|must|may box anywhere (its clauses have no body to guard).

D6 Questions: question mode runs no supersession pass (records and guards never appear in a question; a question compiled with a table holding the rows = today's bytes apart from its record's vocabulary digest). ACE questions cannot name either predicate (no ACE surface); the answers whitelist admits both as semantic predicates (hand-written query fixtures).

D7 Codec (K1): 22 indicators (block + 4 lines); R9 offsets past the insertion point + 4 lines; the q18 fixed-name census covers both new indicators in new cases (frozen payloads stay frozen).

D8 Certification (`emit.rs`, kernel `m6_*`): `project` derives D2 + D4 + D5 from the DRS + the raw table bytes; a dropped, moved or altered record (sentence, citation, url, date), a record in an unsuperseded document, a guard dropped from one clause of a guarded group, a guard on a group without a deontic edge, an altered guard date, a guard after the scope guard and an altered witness pair each fail (`clauses(S)` | the obligation comparison).

D9 Engine + answers + traces: no engine change; both indicators join the semantic set (heads, bodies, NAF payloads, query goals); the comparison = the existing `guideline_satisfies/4`; a proof through a guard holds the consumer's date fact node + `builtin(guideline_satisfies(exactly, D, less, Date))`. Search order: each guarded clause keeps its original body order, the guard appended. The engine scans the whole pending stack for an operator goal's wait (eso), so a guarded body spliced into a caller's continuation puts the guard's still-unbound comparison (a nonground built-in = a barrier) before the caller's later goals: a waiting operator goal can stop waiting earlier than in the unguarded composition. Waiting, first proofs and bound trips can therefore differ in a composition that reaches a guarded clause; the answer sets of finite safe searches stay those of eso D2 (no claim beyond it).

D10 Fork (`ace_to_pl.pl`): mirrors D1–D5 (`sup1_` prefix); the record = a group of kind `supersession` that the renderer prints last and `v1_prove_groups` skips; the per-document replay asserts the D4 witness fact like any other.

D11 Migration (data): `.agent/archive/migrations/revise.py <root> <ckc> --add guideline_supersession/4 --add guideline_evaluation_date/1 --after guideline_exclusion/1 --label sup1 --frozen tests/s1-compiler/ --frozen tests/s1-codec/ --frozen tests/s2-compiler/ --frozen tests/s2-codec/ --frozen tests/nt1-surface/ --frozen tests/cs1/ --frozen tests/cs1-surface/ --frozen tests/bf/probes/` (the CS1 list minus `tests/nt1/`, whose only block-carrying files are the input fixtures `tests/nt1/{patients,policy}.pl.in` of today's reader, so they migrate in the same run (consultant-1 RF9), + the immutable pre-bf `before*` baselines; the list is confirmed by a `--dry` run before Phase A and the final list + each frozen suite's runtime block adapter recorded in the SUP1 commit body), a pure block insertion: no committed table holds a `supersession` or `superseded` row (census = 0 tracked `*vocabulary.tsv{,.in}` rows of either kind), so no clause byte changes (Phase B asserts identity); frozen suites keep their snapshots through their runtime block adapters; new behavior = new fixtures. Idempotent on two fresh base copies (scope sha256 recorded); release inputs amended after the migration commit.

D13 Census checkpoint (C7; SUP2 + SUP3): every planned `supersession` row must retire its whole document; a census case that supersedes only part of a document goes to a MAIN ruling before SUP3 and the cut (split the authoring unit while keeping source fidelity, or add sentence selectors to the row grammar before the freeze). The record already names a sentence, so a selector needs no arity change, but a selector grammar is its own contract ruling. Corroborating sources stay in the census evidence; the record names the operative authority.

D12 Docs: REFERENCE § Vocabulary table (the two kinds + the corpus law), § Compiled Prolog schema (22 indicators; a new subsection "Superseded statements": rows, record, evaluation date, guard semantics, limits; the shared-body sentence names the guard), § Loading a whole knowledge base (the `:- table` directive over 22 indicators; a consumer states `guideline_evaluation_date(<YYYYMMDD>)` to reach a superseded statement as of a date before its effective date), compiler header, `compiler.md`, `queries.md`, `corpus.md` (authoring law: rows, evidence, the census), `rust.md` (harness lines).
