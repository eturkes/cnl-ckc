## Design

D1 Vocabulary kinds `scope` + `exclusion` (spec `vocabulary.rs`, fork `v2_row`, kernel mirror): `scope	<noun>	<key>` names the noun that stands for the guideline's recommendations as a whole and the guideline's key (the docid grammar: nonempty `[a-z0-9-]`, no leading dash, else row law `scope value`; the noun is no unit, frame or grade noun, else `duplicate noun`); `exclusion	<verb>	scope` names the verb an exclusion denies of that noun (value always `scope`, else `exclusion value`). At most one row of each kind (`duplicate scope`, `duplicate exclusion`: the later row reports); each needs the other (`scope without exclusion at row <n>` | `exclusion without scope at row <n>`, checked after the last row, reported at the lone row). Both lemmas name the exclusion form precisely: a subject that names only some recommendations (`an opioid-dosage-recommendation`) would otherwise block the whole guideline (consultant-1). CDC: `scope	recommendation	cdc-2022-opioid` + `exclusion	apply	scope`. `ckc check` (path-aware `vocabulary_check`): for a table at `guidelines/<id>/vocabulary.tsv` the key equals `<id>`, else `scope key at row <n>`; other paths (fixture tables) skip the key law; the UI intake passes the logical path `guidelines/<gid>/vocabulary.tsv` (`rust/ckc/src/ui/intake.rs`) so the key law reaches the review surface with today's error envelope. A scoped document = one compiled with a table holding the pair; everything below applies to scoped documents only (an unscoped document, a table-less one and every question compile as today).

D2 Exclusion record `guideline_exclusion(Key)` (20th indicator, declared after `guideline_unit/3`; semantic predicate: heads, NAF payloads, raw question goals): the recommendations of the guideline `Key` do not apply in this composition. Ground, so neither the record clause nor the guard has a variable of its own (fresh guard variables would each be a singleton: SWI warns "Singleton variable" on consult, consultant-1 K5). The exclusion's content (which subject, which pp object) stays in its negation box; the record clause's trace node names its sentence.

D3 Exclusion sentence = a rule (plain, curried or Horn-split) whose final (curried) consequent box holds exactly one condition, a classical negation box `-(drs(D, Cs))`, such that the anchor-stripped leaves of Cs, in condition order, are one `object(X, N, countable, na, eq, 1)` with N = the scope noun (a plain indefinite: a count or comparison on the subject denies only that many, consultant-1), one `predicate(E, V, X)` (arity 3; V = the exclusion verb) and zero or more `modifier_pp(E, P, Y)`, with E, X ∈ D and every Y ∉ D. It compiles to today's clauses plus one record clause `guideline_exclusion(Key) :- Body` after the last clause of the variant (the box is the whole consequent, so its annotated clauses end the variant), in every variant. Exclusion clauses carry no guard (their only edge is `-`). Worked (CDC): `If a patient has a cancer-related-pain then it is false that a recommendation applies to the patient.` → edge `-`, entity + cardinality (recommendation), event `apply`, arg 1, pp `to`, then `guideline_exclusion('cdc-2022-opioid') :- <the rule body>.` An exception to an exclusion is a `does not provably` condition of the exclusion rule (`If a patient receives a hospital-care and the patient does not provably have a facility-discharge then …`).

D4 Rejects (class `unsupported`, `scope_shape(Why, S)`, scoped documents). Each sentence's scope reasons are checked after its existing translation and the per-sentence duplicate-grade check, so every existing reject of that sentence reports first; sentences in order; within a sentence the first reason in this order reports:
- `deontic_condition`: a should|must|may box anywhere in a rule antecedent or split arm (D6 at compile time).
- `negated_deontic`: a rule consequent with a should|must|may box anywhere inside a classical negation box (a blocked edge would leave the negation box without content).
- `root_deontic`: a root sentence holding a should|must|may box anywhere (no body to guard).
- `root`: a root sentence whose top-level condition list holds a classical negation box with an exclusion-verb `predicate` leaf (an unconditional exclusion).
- `subject`: a rule whose final consequent holds, at its top level, a classical negation box with an exclusion-verb `predicate` leaf whose subject is not a referent of that box (today's `Every recommendation does not apply …`, `No recommendation applies to …`) or whose subject's noun is not the scope noun (`it is false that an opioid-dosage-recommendation applies …`: a per-recommendation scope belongs in that recommendation's own rules, CS2b).
- `consequent`: a rule whose final consequent holds such a box with a box-local scope-noun subject, but D3 fails (other consequent conditions, other box conditions, a subject that is not a plain indefinite, a transitive exclusion event, a pp object local to the box).
Checks read condition structure: the verb, noun and pp checks read anchor-stripped leaves of the named boxes, through the upper-bound group APE builds for `exactly|at most|less than N` (such a subject reaches `consequent`); `subject` + `consequent` read the first top-level negation box of the final consequent that names the exclusion verb, so a second such box is one more consequent condition (`consequent`, reviewer-2 F1 ruling); the deontic checks (`deontic_condition`, `negated_deontic`, `root_deontic`) find a should|must|may/1 compound anywhere inside the named part — APE emits those only as operator boxes, and a match inside leaf data can only add a reject (reviewer-2 F2 ruling). Both lemmas elsewhere (under should or can, in an antecedent, positive, nested under another operator) stay plain data.

D5 Guard: in a scoped document every rule clause whose head is `guideline_operator(_, _, Op)`, Op ∈ {should, must, may} (any depth, every variant), ends with `\+ guideline_exclusion(Key)`, after every other body goal (positive, NAF, built-in). Every other clause stays byte-identical (payload clauses, `-`/`can` edges, asserted heads, exclusion clauses, facts). Witness, Deps, Skolems, ordinals and box numbers unchanged (NAF contributes no witness fact; the guard holds no variable, so `naf_safe` holds and variable numbering is unchanged).
Semantics + limits (REFERENCE): an exclusion whose condition holds in the composition blocks every should/must/may edge of the guideline `Key`; a composition = one patient (CQL `context Patient`): an exclusion that holds for any loaded patient blocks the guideline for all; the absence of an exclusion is not proof of inclusion; read content through its complete operator path from `actual` — a blocked edge's box payload still derives, and a `can` box whose only content is a blocked deontic edge stays as an empty possibility (rec05-imp15 S1–S3); with CS0 an exclusion search cut by a bound makes the result a limit, never a pass.

D6 Guard scan (spec `replay.rs` `recursion_output`, kernel mirror; after the left-recursion scan): when the loaded composition holds a clause whose head is `guideline_exclusion/1`, a clause body (positive goals + NAF payload members, through `','/2`) holding a `guideline_operator/3` goal whose third argument is should, must, may or a variable rejects `proof, scope_condition(Site)` (Site as for `left_recursive`: the first such clause in db order). Meter unchanged. Claim (narrow, consultant-1 K2): guarded heads are exactly the should/must/may edge clauses of scoped documents; with the scan no clause body can resolve against one, so the guards add no negative dependency back into what an exclusion depends on, under leftmost and eso order alike (eso's content-first goals reach payload heads, which carry no guard). Preconditions: the scan ran on the exact composition a consumer loads (`ckc check` runs it on each guideline's corpus; a consumer composing other documents reruns `ckc v1 recursion-check` on its own set). Not claimed: termination or stratification of the authors' own negations, which stay as before (bounded engine; CS0 fail-closed). Without exclusion clauses no check runs (a composition with deontic antecedents and no exclusion stays legal).

D7 Engine + answers + traces: no engine change in this unit (CS0 owns the bounded-negation law; the guard is a negation barrier at the end of its body: eso selection unchanged before it); `answers::goal_walk` admits `guideline_exclusion/1`; a resolved guard = today's `TEv::Naf` event; trace check unchanged.

D8 Codec (K1): 20 indicators (`guideline_exclusion/1` after `guideline_unit/3`; declaration block +2 lines); R9 offsets past the insertion point +2 lines; q18 fixed-name census covers the new indicator in new cases (frozen payloads stay frozen).

D9 Certification (`emit.rs`, kernel `m6_*`): `project` derives D3–D5 from the DRS + the raw table bytes; a dropped, added, moved or rekeyed guard or record, a guard on a non-deontic clause, a guard not last in its body, a record on a non-exclusion rule fails as `clauses(S)` | `projection`; the record's vocabulary digest law as today.

D10 Fork (`ace_to_pl.pl`): mirrors D1–D5 (`cs1_` prefix); the replay module needs no new definitions (the block declares the indicator).

D11 Migration (data): `.agent/archive/migrations/revise.py <root> <ckc> --add guideline_exclusion/1 --after guideline_unit/3 --label cs1` (+ `--frozen` per frozen suite), a pure block insertion: no committed table holds a `scope` or `exclusion` row (consultant-1 K8: tracked `*vocabulary.tsv{,.in}` scope-row census = 0), so no clause byte changes (Phase B asserts identity); frozen suites keep their snapshots through runtime block adapters; new behavior = new fixtures. Idempotent on two fresh base copies (scope sha256 recorded); release inputs amended after the migration commit.

D12 Docs: REFERENCE § Compiled Prolog schema (20 indicators; the shared-body sentence: "every clause of a variant shares one body; in a scoped document a should/must/may edge clause appends the scope guard"; § "Scope exclusions": table row, sentence form, record, guard, rejects, scan + its narrow claim and preconditions, the D5 semantics + limits, inclusion statements = data), § Vocabulary table (kind `scope`), compiler header, `compiler.md`, `queries.md`, `corpus.md` (authoring form; CS2a lands the CDC row).
