# N24 — `just check` speedup at equal strength (contract; archived at unit close)

Row = template refresh find (8681e3a9, O8): `check` = 3232 s of `just gate`'s 5066 s (64 %; final refresh gate: 3221 s of 5023 s) on a 4-core / 8-thread host; inside it every SWI-Prolog subprocess runs one at a time (`ckc check`: 4 compiles per document × 337 + 185 red + 24 green probes + per-question compile/answer/trace runs; the byte-stability pass: compile + certify per document). Accept (the row's check): `check`'s wall-clock before → after on the same host through an equal-strength speedup, every check still running + firing on its planted bad input: `tests/check-mutants` rows, `just late-mutants` rows, the `ui_fixtures` red cases, the byte-stability step failing on a planted fresh-compile drift.

## Tier

shell (unverified gate tooling; no kernel or spec change). Deep by consequence: a scheduling defect would weaken the gate unseen ⇒ firing checks + a closing-diff `reviewer`.

## Design

- D1 `check::par::map(items, f)`: `f` on `CKC_JOBS` workers (positive integer; default = `available_parallelism`); items taken in order; no item taken past a failure already seen; returns the results in item order, or the failure of the lowest failing index = the failure a sequential loop reports (every item below it ran). A worker panic re-raises.
- D2 Applied to independent per-item SWI work: `ckc check` documents (each job = that document's checks in their sequential order: compile ×2, stale, proof ×2, payload, load), red probes, green probes, per-question validation (compile ×2, stale, answer ×2, stale, result shape, trace ×2, stale, trace-check; tallies summed in question order); `ckc compile` per document (compile, write, load, certify, proof); `ckc queries` per question. The aggregate check over the forward + reverse manifests = two concurrent jobs (the reverse job writes its own manifest, so a failure keeps its sequential order); the recursion check, directory swaps and meters stay sequential + after the parallel phase, so stdout keeps its lines + order. Query fixture cases run in parallel per color (each color's directory checks first); each case validates in a private sub-scratch, since every case names its guideline `fx`.
- D3 Unchanged: every check, message, rc, stdout line + order; `CKC_JOBS=1` = the sequential schedule.

## Predicates

- P1 `par::map` unit test `first_failure_in_item_order`: in-order results; a slow early failure reported over faster later ones; empty input. Red on a planted variant that reports the first-completed failure.
- P2 Clean tree: `ckc check` stdout + rc byte-identical between `CKC_JOBS=1` and the default; `ckc compile` + `ckc queries` leave `guidelines/` byte-identical.
- P3 Firing (equal strength): `cargo test --test check_mutants` (97 rows + leftover case) green; `just late-mutants` 4/4 ok (first violation + rc pinned); `cargo test --test ui_fixtures` green (red cases unchanged); planted fresh-compile drift (a committed pl byte changed in a clone) → `ckc compile` + `git diff --quiet -- guidelines/` rc 1.
- P4 Ordering probes in the parallel stage (scratch clone): stale pl planted in two documents → the earlier document's `stale` violation; two red probes made to compile → the earlier probe's `red-exit` violation; same as `CKC_JOBS=1`.
- P5 Timing on this host, quiet (no other build): `just check` before (8681e3a9 gates: 3232 s, 3221 s) → after; `just gate`'s `time: check` at the unit commit.
- P6 full `just gate` green at the unit commit.
