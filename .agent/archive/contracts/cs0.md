# cs0 — fail-closed negation under the search bounds (contract)

Row: `.agent/spec.md` Tasks CS0 (Phase: IMPLEMENT — M7 gap class condition-scope; Decisions: Verification line, Search order). Defect: in the K2 engine (`rust/ckc-spec/src/engine.rs` `step`, `fail`, `run`) a negation `\+ G` runs G at the next depth; a branch of G's search that reaches depth 0 fails with the run's `pruned` flag set, G's search then exhausts, the negation's frame resumes and its continuation runs — the negation holds although G was only cut, not refuted — and `ROut::Sol` ignores `pruned`. A yes/no answer (`answers.rs` `answer_result`: the first proof is conclusive) and a replay obligation (`head_proved`) therefore accept a proof that crosses a cut negation. Measured (consultant-1, `.scratch/agents/cs/consultant-1/bounds-probe.log`, `guideline_range/3` standing in for the CS1 record): an exclusion chain of 105 rule links vs the answer depth 100 → the guarded edge answers `yes` while the exclusion itself answers `indeterminate(limit)` and the edge's trace reads `yes(unproved(finite_failure))`; with 2 links the edge answers `no(finite_failure)`. The K3 trace machine already ends a row as a limit when a negation frame resumes after a cut inside it (`trace.rs` `tfail`, `TAlt::Naf { pruned }` → `TStep::Limit`; prunes inside a refuted negation are absorbed).
User ruling (AskUserQuestion, `.scratch/cs/rulings.md`): fail closed — "the negation fails and the run reports its limit: a yes/no answer becomes indeterminate(limit), an obligation replay fails, a wh-answer stays indeterminate(limit) as today; aligns the answer + replay engine with the trace machine; every negation is affected; tests relying on the old behavior re-pinned with evidence".

## Tier

`kernel`: `ckc-spec` engine (human-read) + uninspected `ckc-kernel` K2 mirror + proofs. No fork, codec, certification, UI or corpus change. Kernel unit flow = `.claude/rules/rust.md` (consultant on this contract, seeded `wt/cs0`, diff-blind tester, reviewer per lens, `just verify` 0/0, `just gate`).

## Design

D1 Negation frame (spec `engine.rs`). The choicepoint a negation site pushes (its continuation) becomes a negation frame that keeps the run's prune flag at site entry; the site runs its inner goal with the flag cleared (as K3 does). Then:
- the inner goal is proved (`NafCut` reached): the flag returns to its entry value — a prune inside a refuted negation is absorbed — and the site fails, as today;
- the inner search exhausts and the frame resumes with no prune inside: the flag returns to its entry value and the continuation runs, as today;
- the frame resumes after a prune inside: the search ends incomplete at once (`Step::Done` with the flag set ⇒ `ROut::End { complete: false, rows }`), whatever choicepoints remain below the frame.
Clause choicepoints, the eso selection rule, the depth passed to the inner goal (d − 1), fuel and transition counting stay unchanged; a frame resume is the same one transition `fail` is today. Fuel exhaustion inside a negation stays `End { complete: false }`.

D2 Consequences (no code change outside the engine), both directions sound: (i) fail-closed — `answers::answer_result` yes/no → `indeterminate(limit)` where today a proof crossed a cut negation (`yes`); `replay::head_proved` false there ⇒ `obligation_failed(…)` in aggregate-check; (ii) absorption — today the prune flag is sticky, so a prune inside a refuted negation makes the whole run incomplete; with D1 it does not, so a yes/no search that otherwise exhausts cleanly ends `no(finite_failure)` (today `indeterminate(limit)`) and a wh search `solutions(…)` (today `indeterminate(limit)`). A search that exhausts after a cut negation's frame resumed cannot occur (D1 ends it there). `v1 trace` unchanged (K3 already behaves so); recursion-check unaffected (no search).

D3 Kernel (`k2_engine.rs` + its proofs, `k2_walk.rs` / `k2_select.rs` where the frame shape reaches them): the exec machine refines D1; `just verify` 0 errors 0 warnings with every theorem kept.

D4 Docs: REFERENCE § Query answers (yes/no conclusiveness: a cut negation makes the result a limit) + § Compiled Prolog schema (the native bounded replay: a cut negation never proves an obligation; the fork's per-document P7 replay and any consumer wrapping SWI in `call_with_depth_limit` stay fail-open — measured, consultant-1 `p7-depth.log`: a negated walk past depth 4000 succeeds under the exact P7 wrapper — so `ckc check`'s native aggregate replay and `ckc certify` are what reject such a document), `queries.md`, the engine header comment.

## Predicates (acceptance; seed-red unless marked `already-passing`)

- P1 answers (`ckc v1 answer`, hand-sized canonical documents): a yes/no question whose only proof crosses a negation whose inner search is cut by the depth bound → `indeterminate(limit)` (today `yes`); the same with a shallow refutable inner search → `yes` (already-passing); an inner proof found after a cut branch inside the same negation → the negation fails cleanly and the run stays complete: `no(finite_failure)` when nothing else proves the question (today `indeterminate(limit)`), and a wh question over the same composition gives its complete `solutions(…)`; a cut inside a nested negation whose frame resumes → `indeterminate(limit)`; a wh question whose search crosses a cut negation that resumes → `indeterminate(limit)` (already-passing); a cut outside any negation followed by a clean proof → `yes` (already-passing: positive proofs stay conclusive); fuel exhaustion inside a negation → `indeterminate(limit)` (already-passing).
- P1b distinguishing cases (consultant-1 Z4): (a) entry-prune restoration — an ordinary branch prunes before a negation site; with the negation then holding cleanly and with it refuted, a wh search over the composition stays `indeterminate(limit)` and an independent later positive proof of a yes/no question stays `yes`; (b) no outer rescue — an early clause reaches a negation frame that resumes after a cut, a later clause would give a shallow proof: the answer is `indeterminate(limit)` (no proof tried after the frame), and a ground wh row recorded before the frame does not make the enumeration complete; (c) nesting through clauses — a negated predicate whose clause body holds another negation: an incomplete inner negation ends the whole run even where an outer alternative could prove the inner goal, while a positive depth-cut branch followed by an inner proof is absorbed; (d) a nested case whose result is `yes` today and `indeterminate(limit)` after (e.g. three negation layers), unchanged-limit nested controls labelled already-passing; (e) result precedence kept — a nonground row recorded before the new early stop still rejects `nonground_solution(Qid)`, one that only a later branch would reach is no longer reached; (f) fuel exhaustion inside a negation stays `indeterminate(limit)` with the transition count unchanged on every path that does not resume a cut frame.
- P2 replay (`ckc v1 aggregate-check`, replay depth 4000): an obligation whose head's proof crosses a cut negation → `obligation_failed(…)` (today ok); the knowledge-only composition of the same documents → ok.
- P3 traces: for every P1 case, `ckc v1 trace` over the new answer exits 0 and mirrors it (a `no` or limit answer gives the matching trace result), and `trace-check` keeps its demonstration law (accepts a positive proved answer, rejects `no` / limit / empty solutions as `trace_check(non_demo)`) — an already-passing control: K3 is unchanged (tester-1). A limit or `no` trace mirrors the supplied answer rather than re-proving its class, and K2/K3 keep their other differences (site-local trace depth, fuel scope, K3's NAF-safety cut): no global answer/trace equality is claimed (consultant-1).
- P4 regression: every committed `tests/v1` + `tests/queries` + corpus query artifact either stays byte-identical or is re-pinned in this unit with its old + new output and the cut negation that explains the change (a census of changed pins in the commit body); `ckc check` verdicts on the corpus unchanged; `just gate` green; Verus `--no-cheating` 0 errors 0 warnings; seed-red + already-passing cases recorded apart in the commit body.
