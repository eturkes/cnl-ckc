## Design

D1 Numbers (spec, new module or `compare.rs`). A number term = `Int(n)` or `rational(P, Q)` = `Comp("rational", [Int(P), Int(Q)])` with Q ≥ 2 and gcd(|P|, Q) = 1; value = P/Q. Every other term (another arity, a non-integer argument, Q ≤ 1, an unreduced pair such as `rational(2,4)`, `rational(0,2)`, `rational(3,1)`, `rational(1,-2)`) is no number. The numeric reading applies only in numeric argument positions of the built-ins: K1 keeps admitting generic compound data, so a malformed `rational/2` term is readable data that fails evaluation, and the lemma atom `rational` stays legal. `gcd(a, b)` = Euclid (`b == 0 → a`, else `gcd(b, a % b)`), constructive. `canon(p, q)` (q ≥ 1) = the number term of p/q: divide by gcd(|p|, q); denominator 1 → `Int`, else `rational`. Each rational value has exactly one number term ⇒ structural unification of admitted ground number terms = numeric equality. Answer sorting stays structural (integers precede compounds; no numeric sort is promised). No floats (R21 stays).

D2 Value sets. A (comparison, count) pair with a number count denotes: `exactly x` = {x}; `eq x`, `geq x` = [x, ∞) (nt1 ruling: a plain number states at least that many); `greater x` = (x, ∞); `leq x` = (−∞, x]; `less x` = (−∞, x). `about`, `na`, any other atom, a non-number count → no value set. Spec ghost type `VSet = Point(r) | Lower(r, closed) | Upper(r, closed)`; a result spells back as `exactly` | `geq` | `greater` | `leq` | `less` + the canonical count — never `eq`.

D3 Product image `vprod(a, b)` = the exact set {u·v : u ∈ a, v ∈ b} when it is a point or a ray, else none (the whole line). With att(x, c1, y, c2) = (x = 0 ∧ c1) ∨ (y = 0 ∧ c2) ∨ (c1 ∧ c2):
- Point(0) × any = Point(0) (both orders; checked first, so the rows below see nonzero points and stay mutually exclusive); Point(x) × Point(y) = Point(xy);
- Point(x > 0) × Lower(y, c) = Lower(xy, c), × Upper(y, c) = Upper(xy, c); Point(x < 0) flips: × Lower(y, c) = Upper(xy, c), × Upper(y, c) = Lower(xy, c) (both orders);
- Lower(x, c1) × Lower(y, c2) = Lower(xy, att) iff x ≥ 0 ∧ y ≥ 0;
- Upper(x, c1) × Upper(y, c2) = Lower(xy, att) iff x ≤ 0 ∧ y ≤ 0;
- Lower(x, c1) × Upper(y, c2) = Upper(xy, att) iff x ≥ 0 ∧ y ≤ 0 (both orders);
- every other pair = none.
Soundness = a kernel theorem (`vprod_sound`), quantified over mathematical rationals with positive denominators (term syntax stays in the decoder): for every a, b with vprod(a, b) = Some(r) and every u ∈ a, v ∈ b, u·v ∈ r — a derived bound never excludes a true product. Exactness (every member of r is some u·v; none ⇔ the whole line) = argued here + graded by the tester's independent interval oracle, not a theorem.

D4 Quotient image `vquot(a, b)` = vprod(a, Point(1/y)) iff b = Point(y) with y ≠ 0, else none: division requires an exact nonzero divisor (a ray, zero, `about` or `na` divisor derives nothing — a scoped incompleteness, not a claim that every representable quotient is computed; the exact image of a division by a ray can be a bounded interval, which one comparison cannot state).

D5 Built-ins (schema built-ins like `guideline_satisfies/4|6`: never a head, never declared, no clause in any document; legal as a positive body goal and inside a NAF payload; reserved names):
- `guideline_product(S1, N1, S2, N2, S, N)` holds ⇔ S1, S2 atoms with value sets a = V(S1, N1), b = V(S2, N2), vprod(a, b) = r, and (S, N) = the spelling of r.
- `guideline_quotient(S1, N1, S2, N2, S, N)` holds ⇔ the same with vquot.
The first four arguments are inputs; S, N are outputs. A call yields at most one solution, raises no error and binds nothing but S and N.

D6 Comparison built-ins over rationals (`compare.rs`): `guideline_satisfies(S, N, B, M)` and `/6` take number counts and bounds (D1); `within` compares rational values (x ≥ y ⇔ p1·q2 ≥ p2·q1 with positive denominators); `/6` scales both by their unit ratios (integers) first. Integer-only verdicts unchanged.

D7 Engine (K2, `engine.rs`). A selected arithmetic goal with depth > 0 = one transition: inputs decode (D1, D2) and the image exists → unify (S, N) with its spelling across the stack + solution template, choicepoints keeping their own copies (as head unification does; a clash = `fail`); otherwise `fail` (finite failure, no prune; backtracking resumes the newest choicepoint). Depth 0 → pruned fail before evaluation, as every goal. eso: `binds` excludes every schema built-in from context-binding candidates; a built-in with any nonground argument, an output included, ends the run; a fully ground built-in stays a scan-through goal (its verdict is fixed, it binds nothing); conjunction expansion keeps the eso law, and after expansion the stack-level barrier applies. In compiled documents an output is never a box context (an authoring invariant, not a K1 theorem: a raw query may alias one). Replay (P9) + recursion-check unchanged (no clause heads a built-in; witness facts already exclude built-in goals, `emit.rs` `is_builtin_lit`). `answers::goal_walk` admits the arithmetic built-ins with the comparisons (ACE questions never emit them; the whitelist = the public vocabulary).

D8 Traces (K3, `trace.rs`). A resolved arithmetic goal = one transition that applies its output bindings to the machine's stack (`tunify`); outside a negation it logs a leaf `builtin(G)`, G = the goal with its outputs bound (ground). The soundness proof extends the certificate substitution with the output unifier before recording the leaf (today `record_builtin` keeps `theta`), keeping earlier ground leaves + safe NAF payloads and the fresh-variable bounds (computed numbers and comparators carry no variables). `node_valid` keeps `t == apply(g, th) && holds(t)` with `holds` extended by D5; no clause digest, no materialization charge, the `nodes=` meter counts clause nodes. Inside a negation nothing is recorded (as today). Trace check: re-derivation + byte equality, then the digest join, as today.

D9 Codec (K1, `v1text.rs`): a body literal (Pos + Naf members) = a semantic predicate or a built-in (comparison or arithmetic); heads + declarations unchanged (20 indicators, no block change ⇒ no expected document-byte change; the fresh compile + queries of `just check` must reproduce those bytes, as Schema evolution requires); R9 offsets as today.

D10 Schema file (`compare.rs` `schema_bytes`, generated; ckc compile writes it, ckc check rejects absent/stale/nonregular as today): ISO Prolog only, no cut. For the public product/quotient predicates all four inputs are validated without binding them before arithmetic; outputs stay unrestricted terms that unify only with the computed canonical pair (computed in fresh local terms first, so aliases behave as in the engine). Comparisons validate all their inputs and bind none. Finite well-typed calls yield 0 or 1 solutions with no type or instantiation error, provided the host represents every intermediate integer (cross products, `abs`, gcd steps); SWI 9.2.9 has unbounded integers; resource exhaustion lies outside this guarantee. The byte theorem proves the emitted text, not an external engine's execution: native refinement + soundness are machine-verified, SWI behavior is graded by the differential test. Adds `guideline_number/3` (D1 decode: integer → P/1; `rational(P, Q)` → guards + `guideline_gcd/3`), the value-set decode, the D3 case table, `guideline_quotient/6`, canonical spelling via `guideline_gcd/3` (`//` exact), and rewrites `guideline_satisfies/4|6` over rationals by cross-multiplication; private helpers keep explicit input modes. The header names generated first-party code under Apache-2.0 WITH LLVM-exception as today.

D11 Kernel: arbitrary-precision magnitudes stay decimal digit vectors; magnitude primitives = add, subtract (ordering precondition), schoolbook multiply and positive-divisor divmod (long division: one quotient digit 0–9 per step), each refining `int` arithmetic; canon = exact division by the Euclidean gcd (an algorithm change needs the same refinement + a representative large-operand cost); value size is unbounded by the model, and transition fuel bounds goal dispatches, not digit work or allocation; number decode, canon, VSet, vprod, vquot refine D1–D4, `vprod_sound` (+ the quotient corollary through the reciprocal) proves D3; K2 + K3 steps refine D7 + D8 with every theorem kept (`k3_sound_*` gains the binding step). No machine-integer narrowing (nt1 precedent): the kernel computes exactly what the spec computes for every input size.

D12 Fixtures: `guidelines/schema.pl` re-derives (release manifest row → `just amend-manifest` after the commit); suites pinning schema-file bytes re-pin through the generator, the churn = D10 alone; no `guidelines/*/pl` byte changes; review manifest unchanged.

D13 Docs: REFERENCE § Comparison conditions (rational counts) + a new § Arithmetic built-ins (numbers, value sets, D3/D4 table in prose, the limits: no derivation from a whole-line product, a non-exact or zero divisor, `about`, `na`; a built-in that derives nothing does not make the expression false; termination: an emitted rule can be operationally recursive even when its unit dependencies are acyclic — plain leftmost Prolog may diverge, tabling terminates the measured conversion fixture but proves no general termination, the native bounds return explicit limits and establish neither completeness nor a wall-clock bound) + § Query answers (cost model: one inference per built-in) + § Proof traces (arithmetic leaves); `queries.md`, `rust.md` (harness + modules).

## Predicates (acceptance; seed-red unless marked `already-passing`, those credited by mutation or proof)

- P1 numbers: every built-in (native engine + SWI over the schema file) treats integers and canonical `rational(P, Q)` as numbers; every input number slot fails, without exception, on `rational(2,4)`, `rational(0,2)`, `rational(3,1)`, `rational(1,0)`, `rational(1,-2)`, `rational(a,2)`, `rational(1,_)`, `rational(_,2)`, `rational(1,2,3)`, atoms, variables, lists and other compounds; outputs follow occurs-check unification against the computed canonical result (unbound or partially bound outputs can succeed, incompatible ones fail); canonical results only (a computed integral value spells `Int`).
- P2 comparisons: `guideline_satisfies/4|6` over every (stated, bound) pair × values at, just below and just above the bound in integer and rational spellings (denominators 2, 3, 7, 10^k; huge numerators) × same-unit, cross-unit and cross-group cases = an independent rational oracle in both engines; integer-only grid verdicts identical to nt1's (already-passing).
- P3 product: every (point | lower | upper) × (point | lower | upper) × sign class of each bound (negative, zero, positive) × closedness = an independent interval oracle (result spelling or failure), in both engines, both argument orders; outputs unbound → bound to the canonical spelling; outputs pre-bound to it → success; pre-bound to another value, to `eq`, or to an unreduced spelling of the same value → failure; ill-typed or unbound inputs → failure without exception.
- P4 quotient: exact nonzero divisors (integer, rational, negative) = product with the reciprocal; zero, ray, `about`, `na` divisors → failure.
- P5 engine (`ckc v1 answer`, hand-written canonical documents): a rule whose head cardinality takes a product or quotient chain derives the canonical value (yes/no + wh); a bounded fact propagates (`geq 60` × `exactly 3/2` → `geq 90`); a failing built-in backtracks into the preceding goal's next clause; eso: an operator goal ahead of a nonground arithmetic goal does not wait past it (leftmost answer kept), a ground pre-bound arithmetic goal is scanned past (success and failure cases before a later relational context binder), a partially bound output inside a query conjunction; transition counts: one per built-in dispatch, a failed output unification included, no built-in choicepoint (an inference-bound boundary case); depth 0 prunes before arithmetic.
- P5b binding + rollback: one shared variable as both outputs; an input aliased to an output (input unbound ⇒ failure, no inverse solving); a partially instantiated output; two built-ins where the second consumes the first's result and the answer template shows it; a later clash restores the preceding choicepoint's values.
- P5c negation: a successful computation refutes its NAF; an invalid or unrepresentable input makes the built-in fail and the NAF succeed; bindings inside never escape; depth 0 inside a negation reports a limit (cs0 fail-closed), never success.
- P6 traces: arithmetic leaves carry the evaluated goal, as roots and as children; `trace-check` rejects a leaf with a wrong result, an unreduced spelling of the right result, a changed input that keeps the product true, and an `eq` result; arithmetic inside a negation records nothing.
- P6b large + canonical arithmetic: large numerators and denominators (100+ digits), gcd cancellation to an integer, zero canonicalization, negative divisor normalization, coprime and large-common-factor operands — examples, not an input-size cap.
- P7 codec: both arithmetic built-ins legal in positive bodies + NAF payloads, rejected as heads (R9 offset) and absent from declarations; a query goal naming one passes the whitelist.
- P8 replay + recursion: an aggregate-check over hand-written documents whose obligations need a product (payload heads carry the computed value) → ok; a payload with the wrong value → `obligation_failed`; recursion-check verdicts unchanged.
- P9 schema file: the new bytes = `schema_bytes()`; `ckc check` rejects the old file as stale; SWI 9.2.9 consulting the file gives the P1–P4 verdicts with `findall` multiplicity 0 | 1, no exception, no warning; the release archive ships it under the unchanged load line.
- P10 soundness bridge (machine-verified, `--no-cheating`): `canon(p, q)` is an admitted canonical number of value p/q for q > 0; every successful public product/quotient evaluation returns a canonical pair whose decoded set is the D3/D4 image and contains every product (quotient) of input values — through `vprod_sound` + reciprocal scaling + decode/encode lemmas, or stated directly over decoded public terms. Planted errors (Lower × Lower without the sign guard; a wrong canonical sign or normalization) fail the theorem.
- P11 gates: `just gate` green; `just verify` 0 errors 0 warnings; trust re-pinned; the corpus + 6 queries byte-identical; each test labelled seed-red or already-passing (e.g. ill-typed rational comparison inputs, arithmetic heads at K1 and unchanged recursion verdicts already pass), the latter credited by proof or the mutation run per `rust.md`; recorded apart in the commit body.
