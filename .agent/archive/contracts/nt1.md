## Design

D1 Comparison relation (spec `compare.rs`; one table shared by the engine, the trace check and the schema file). Stated ∈ {`eq`, `exactly`, `geq`, `greater`, `leq`, `less`}; Bound ∈ {`exactly`, `geq`, `greater`, `leq`, `less`}; integer endpoints (R21: no floats) over a dense value domain, arbitrary precision (the kernel's decimal magnitudes, no machine-integer narrowing). `within(S, X, B, Y)` ⇔ V(S, X) ⊆ V(B, Y), V(eq, x) = V(geq, x) = [x, ∞) (ruling), V(exactly, x) = {x}, V(greater, x) = (x, ∞), V(leq, x) = (−∞, x], V(less, x) = (−∞, x):
- B = geq: S ∈ {eq, exactly, geq, greater} ∧ X ≥ Y.
- B = greater: S ∈ {eq, exactly, geq} ∧ X > Y; S = greater ∧ X ≥ Y.
- B = leq: S ∈ {exactly, leq, less} ∧ X ≤ Y.
- B = less: S ∈ {exactly, leq} ∧ X < Y; S = less ∧ X ≤ Y.
- B = exactly: S = exactly ∧ X = Y.
Dense order = MAIN choice: sound for whole counts; conservative where an entailment holds only for whole counts (`more than 49` does not meet `at least 50`; `more than 23 hours` does not meet `at least 1 day`); still sound if a later revision admits non-integer quantities.
Units (fixed ratios): group `time` = second 1, minute 60, hour 3600, day 86400, week 604800; group `calendar` = month 1, year 12; a day and a month never compare.
- `guideline_satisfies(S, N, B, M)` holds ⇔ S, B atoms of the domains above, N, M integers, `within(S, N, B, M)`.
- `guideline_satisfies(S, N, U, B, M, V)` holds ⇔ the same with U, V unit atoms of one group, `within(S, N·r(U), B, M·r(V))`.
Any other argument (variable, other atom — `about`, `na` included — compound, a unit outside the table, two groups) ⇒ false. Both are schema built-ins, not document predicates: never a head, never declared, no clause in any document; legal as a positive body goal, inside a NAF payload and as a question goal; a built-in binds nothing and leaves no choicepoint.

D2 Unit annotation `guideline_unit(Context, Quantity, Unit)` (19th indicator, declared after `guideline_qualifier/4`; semantic predicate: heads, bodies, NAF, raw question goals): Quantity's count is stated in the calendar unit Unit. With a table, every referent whose `object/6` noun has a `unit` row (q12 D3 whole-DRS classification: the time quantity, claimed by a pattern or not, `about` included) emits it right after its cardinality literal, in that literal's context, in every position (root fact, consequent head, antecedent goal, NAF payload, question goal after its flatten + annotation pass). Without a table: never. Not a q12 pattern claim. Codec = arity + canonical form; the unit domain = certification law.

D3 Conditions. In a body (rule antecedent, every Horn-split variant, NAF payload) and in question goals, a referent R whose object comparison C ∈ {exactly, geq, greater, leq, less} expands with fresh variables (allocated after the DRS referent enumeration, never in a Deps, Skolem or witness identity slot; distinct per R; NAF-local inside a payload):
- R not a time quantity: `guideline_entity(Ctx, R, Noun, Class)`, `guideline_cardinality(Ctx, R, Unit, S, N)`, `guideline_satisfies(S, N, C, Count)`.
- R a time quantity of unit U0: `guideline_cardinality(Ctx, R, Unit, S, N)`, `guideline_unit(Ctx, R, V)`, `guideline_satisfies(S, N, V, C, Count, U0)` — no entity literal (its noun names U0, which the unit literal carries; the source noun + class leave the body); every annotation literal of the same body that names R as a quantity carries V in its unit slot (interval quantity → Unit; recurrence gap → Unit; window gap → GapUnit; window length → LengthUnit), linked by R, whatever the pp order.
- Every other referent (`eq`, `about`, `na`), every head + root fact, frequency periods (`eq` by q12) and q13 range high ends (`eq` by q13) keep today's literals (+ D2 for time quantities). A frequency counted item converts as any non-time referent.
Question admission stays as c1 rules it (without a table an upper-bound determiner's condition list still rejects `query_unsupported(leaf(list), 1)`): D3 converts the goals of admitted questions only. Order inside a clause = today's condition order; R's expansion stands where its entity + cardinality literals stood. Referent ordinals, box numbers, Deps + Skolem terms unchanged (ordinals enumerate DRS conditions).
Worked examples (CDC):
- rec04-imp07 `includes at least 50 MME-units-per-day` ⇒ body `guideline_entity(actual,B,'MME-unit-per-day',countable), guideline_cardinality(actual,B,na,C,D), guideline_satisfies(C,D,geq,50)`.
- s42-15 `includes more than 3 days` ⇒ `guideline_cardinality(actual,F,na,G,H), guideline_unit(actual,F,I), guideline_satisfies(G,H,I,greater,3,day)`; facts `exactly 1 week` and `1 week` (eq) meet it, `exactly 3 days` does not, `exactly 1 month` does not (groups differ).
- question `tablet-use-spacing` `at an interval of at least 4 hours` ⇒ `guideline_recurrence(actual,D,C,V)` + `guideline_satisfies(S,N,V,geq,4,hour)`; rec01-imp03's fact (`geq 4`, `hour`) meets it (reflexive).

D4 Safety + witness. `head_safe` unchanged (no head names a fresh variable). `naf_safe`: a NAF payload's D3 variables join the payload-local set, and `body_doms` / `expanded_len` follow the new expansion lengths positionally. Obligation witness: S ↦ C, N ↦ Count, V ↦ U0 beside today's referent + context bindings; Facts = the positive body goals minus built-in goals, under that substitution ⇒ each built-in holds reflexively (V(C, Count) ⊆ V(C, Count) for every convertible C) and the obligation stays modus ponens over the document's own clauses. Prediction: a non-time conversion leaves its payload bytes unchanged; a time quantity adds its unit fact and, when converted, drops its entity fact.

D5 Engine (K2, `engine.rs`). A built-in never binds and never waits: `binds` returns false for both built-in indicators. In the eso run a nonground built-in is a barrier, as a negation is (`run_binds` stops there), so an operator goal never waits past an unbound filter and the filter never runs before the goal that leftmost order would run first; a ground built-in is scanned past (its verdict is fixed). Inside a conjunction goal `binds` looks through every leaf, as eso does for negations (a split evaluates nothing; after the split the stack-level barrier applies). A selected built-in goal with depth > 0 = one transition: holds → the stack minus that goal; else `fail` (finite failure, no prune; backtracking resumes the newest choicepoint, e.g. the preceding cardinality's next clause). Depth 0 → pruned fail before evaluation, as every selected goal. Replay (P9) + recursion check unchanged (no clause heads a built-in; a built-in leftmost goal never unifies with a head). `answers::goal_walk` admits both built-ins.

D6 Traces (K3, `trace.rs`). A resolved built-in goal = one transition + a leaf `builtin(G)`, G = the goal as called (ground, so later substitutions leave it unchanged); no clause digest, no whole-run materialization charge; the `nodes=` meter keeps counting clause nodes. `node_valid`: a builtin leaf certifies goal g under θ ⇔ G = θ(g) ∧ G holds. A question's comparison goal = a builtin root (REFERENCE "Root nodes are always clause nodes" → clause or builtin roots). Inside a negation nothing is recorded (as today). Trace check: full re-derivation + byte equality first (a changed but still true builtin argument fails), then the digest join over clause nodes.

D7 Codec (K1, `v1text.rs`): 19 indicators (`guideline_unit/3` after `guideline_qualifier/4`; declaration block +2 lines); head literal = semantic predicate; body literal (Pos + Naf members) = semantic predicate or built-in; R9 offsets as today. Raw query goals stay generic terms at K1 (the answer whitelist owns names). Answers + traces grammar unchanged (`builtin/1` is a ground term).

D8 Certification (`emit.rs`): `project` + `project_query` derive D2 + D3 from the DRS + the raw table bytes; a changed, dropped, added or misplaced built-in or unit literal, a wrong bound, unit or variable link, a kept entity literal on a converted time quantity or a dropped one elsewhere fails as `clauses(S)` | `projection`. Schema-file bytes = a `ckc check` law (D10), not a certification input.

D9 Fork (`ace_to_pl.pl`): mirrors D2–D4 (after `v2_annotate` + `s1_strength` on antecedent items + NAF payloads, and on question goals); its per-document replay module defines both built-ins with D10's clauses.

D10 Schema file (ruling: generated): `guidelines/schema.pl` = the spec's `schema_bytes()`: one header comment naming generated first-party code under `Apache-2.0 WITH LLVM-exception` + `guideline_satisfies/4` and `/6` (every public argument guarded by `atom/1` | `integer/1` before any helper runs) + `guideline_within/4` (one clause per D1 row, ISO `>=` `>` `=<` `<` `=:=`) + `guideline_scale/3` (one fact per unit); every call yields 0 or 1 solution, raises no error and binds no argument. The file is a common payload member, not a guideline: the one root-path exception is applied consistently to the guideline-entry inventory (only this regular file, exact bytes), the tracked-Prolog inventory, the release partition (shipped whatever the guidelines' rights profiles) and the archive load line (`meta replay load:` names it before the document). `ckc check` rejects an absent, stale or nonregular file; README-dist + REFERENCE state that a consumer loads it with the documents. Portability: ISO predicates only; exact results need the host's integer range to cover counts × 604800 (SWI 9.2.9 = unbounded, the demonstrated host).

D11 UI (K5). Every bound consumer recovers a converted bound through its built-in's variable links: timing rows (duration, after, before, within, recurrence, window gap + length, q13 range low end, frequency counted item via `count_html`), condition + excluded-condition parts alike; unit words from the bound unit. Action nouns (MAIN ruling on consultant-1 K9): where a preference or qualifier row's Action names a converted time quantity — a copula subject (both tables), or the event's second participant (qualifier table; a preference row's Action names the verb or a copula subject alone, so its other participants never reach it) (`If a treatment usually takes at least 2 days then …`) — it names the bound's unit word (`days`), because the quantity has no noun literal left; a table alias (`d → day`) therefore reads as the canonical unit. Unaffected visible table content stays byte-identical; the compiled-Prolog disclosure, its line count (+2 declaration lines + each unit head), hidden custody digests + review status follow the predicted D2/D3 output. No new table (ruling).

D12 Migration + oracle. Extend `.agent/archive/migrations/revise.py` with the nt1 semantic migration, then invoke it with repo-root + the nt1 binary + `--add guideline_unit/3 --after guideline_qualifier/4 --label nt1`: the extended run inserts the declaration pair, seeds `guidelines/schema.pl` in the input census, regenerates the D2/D3 corpus + fixture outputs, preserves frozen oracle sources (their projection adapters gain the D2/D3 erasure), and validates the churn against the independent nt1 oracle; no former equality assertion becomes an unchecked re-pin. Idempotent, two fresh base copies byte-identical (scope sha256 recorded). Oracle (tester, diff-blind to the migration) predicts from source occurrence identity (the frozen DRS / old clauses supply each ordinal's noun, class + bound; it never calls the graded implementation): +2 declaration lines; one unit literal per time quantity (facts, heads, bodies, question goals; each root/consequent one = a clause line); every convertible body or question cardinality → the D3 triple; payloads per D4; review bundle v2 digests change exactly where the clause stream changes; question projections + query digests → answer + trace custody (answer sets of the 6 corpus queries unchanged; unit facts + builtin leaves enter traces); UI deltas per D11; the schema member + load line in the release manifest; erasing D2 literals + reverting D3 (noun + class restored from the source occurrence) yields the pre-nt1 compile byte for byte apart from the declaration block + digests. Self-plants fire. Graded on the pure-migration tree: 0 unpredicted.

D13 Consumer semantics + limits (REFERENCE § Compiled Prolog schema gains this paragraph; `compiler.md`, `queries.md`, `ui.md` follow): dense value sets with integer endpoints = a conservative entailment over whole counts (it can miss an entailment that holds only for whole counts, in one unit or across units); a plain-number condition keeps exact structural matching; `about` carries no tolerance (q13); a q13 range states an uncertain minimum θ in [low, high], not a value interval, and its high end + frequency periods keep exact matching; ACE root facts cannot state an exact value (root upper bounds reject), so a consumer supplies exact patient values through the public schema (`exactly`; FHIR quantities without comparator → `exactly`, with comparator → `geq|greater|leq|less`) + a `guideline_unit` literal on each time quantity. Today's claims "no unit conversion" + "a fact for `geq 30` does not satisfy a goal for `geq 20`" (REFERENCE § Compiled Prolog schema, § Vocabulary table and time annotations) give way. `guidelines/schema.pl` belongs to the portable product; native consumption stays Rust (Decisions: Language boundary).

## Out of scope
