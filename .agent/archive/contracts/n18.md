# N18 — own pins follow upstream (contract; archived at unit close)

Row = queue-run find, opened + closed in the N18 commit (its row text = this contract): sha2 0.11.1 shipped 2026-10-12, while ckc pins sha2 `=0.11.0`; `just outdated` reported `crate:sha2 0.11.0 0.11.1 held by ckc 0.1.0`, and a held crate never turns the weekly job red. User ruling (AskUserQuestion #2): own pins follow upstream — `just outdated` reports a crate held only by a workspace member's own `=` requirement as drift (rc 1), approving that change to the N10 `held` rule; sha2 0.11.1 lands as its own unit (N19).

## Design

- D1 `outdated` reads each workspace's member requirements through `cargo metadata --format-version 1 --no-deps --offline` (cwd `/`, the dry run's empty CARGO_HOME + pinned rustc), as `member version crate req` rows; a failed call or unparsable output = an error row `cargo-metadata:<manifest>` + rc 2.
- D2 a crate the dry run cannot move whose every direct dependent (Cargo.lock edges) is a member requiring it with `=` = `drift` + `pinned by <member> <version> (<req>)`, counted as drift; any other hold stays `held` (a member's non-`=` requirement, an external dependent).
- D3 `_relock` (under `bump-crate`) rewrites a member's inline `=` requirement on the crate (`<crate> = "=v"` | `<crate> = { version = "=v", … }`, in `rust/Cargo.toml` + `rust/*/Cargo.toml`) to `=<version>` before the relock; the existing trust re-pin covers the manifests.
- D4 checks in `rust/ckc/tests/recipes.rs`: an `outdated` fixture (own `=` pin, member caret hold, external hold, ok, metadata failure) with exact stdout + rc; a `bump-crate` fixture (own pin moved; a caret requirement, a `sha2-extra` prefix twin and the workspace vstd pin untouched; cargo calls exact); each with its planted pre-rule form, which must slip through.
- D5 law: spec Decisions (deps bullet), `rust.md` dependency bullet (rule + firing) + recipe-check bullet.
