# N2 — review records the rendered commit (contract; user approval before production edits)

Row (`.agent/deferred.md` "Review records the rendered commit"; closing review F-C04; user ruling = the viewed commit): `ckc ui` records the HEAD current at POST time (`rust/ckc/src/ui/request.rs` `post_models`: `config.commit` ∨ `corpus.commit`). The guard chain refuses a decision whose bundle changed since render, so that commit holds the reviewed bundle; a HEAD move between render and POST that leaves the document alone makes the row name the later commit. Row acceptance: the page carries its rendered commit; POST records it only after bundle v2 at that commit equals the posted digest; ui_socket probe: render at A, unrelated commit B, POST → row names A; a forged commit id → refusal with no ledger write.

## Tier

kernel — K5 spec `rust/ckc-spec/src/ui.rs` + kernel `k5_*` (exec + proofs, generated K5 files via `.agent/archive/generators/`) + `contract.rs` bindings (trusted surface grows: ui.rs fields/guard/`posted_commit`, v1text `hex40`, 4 copy-table literals ⇒ `ckc trust-audit --write rust`, spec meter up) + shell `rust/ckc/src/ui/{corpus,request,pages}.rs`. Battery: contract committed first; diff-blind `tester` (red suite from P3–P5); blind `reviewer` pair on the kernel diff before its commit; Verus `--no-cheating`; full `just gate`.

## Design

- D1 page: `render_document` gains a `commit` input beside `token` = the snapshot commit the page renders (git mode: `Corpus::committed` HEAD, 40 lowercase hex; filesystem mode: empty; `ckc ui request --commit <c>`: `<c>`). The form gains `<input type="hidden" name="commit" value="…">` after `ledger_sha256` (attribute = invisible; no visible copy change).
- D2 parse: `field_names` += `commit`; `parse_fields`: commit = empty ∨ `hex40` (new spec fn beside `v1text::hex64`: length 40 ∧ `is_hex_lower_b`), else 400 via `bad_form` (visible copy = the existing invalid-form sentence; detail `ui: verdict: invalid commit` rides the HTML comment like `invalid review_sha256`). Missing/duplicate → the existing field errors.
- D3 shell: new binding `ui_posted_commit(req) -> Option<Vec<u8>>` = spec `posted_commit` (`parse_form` Ok ⇒ its commit field) ⇒ the shell reads the field through the verified parser, never its own. POST on a document route, git mode, posted `c` nonempty: `c` = snapshot commit ⇒ reuse the HEAD derivation (the snapshot here = this POST's own `Corpus::committed` read, so equality = HEAD unmoved since render); else `git cat-file -e <c>^{commit}` → (D7) `git merge-base --is-ancestor <c> HEAD` → `git archive <c> guidelines` (the `Corpus::committed` preflight + extraction, parameterised by commit) → `fresh::derive` ⇒ `at_commit = Some((c, review digest of the docid at c))`; any failure ⇒ `None`. Client bytes reach git only after the 40-lowercase-hex gate (kernel parse rule, rechecked in the shell) as a revision that cannot open with `-`; the gid comes from the corpus guideline list. The shell never decides acceptance.
- D4 guard (spec `prepare_candidate`, after the subject-changed + ledger-changed guards, both kept): `PostState` gains `commit` (the snapshot commit; empty = filesystem mode); `PostDocument.commit` → `at_commit: Option<(Bytes, Bytes)>`; accept iff (`s.commit` empty ∧ `f.commit` empty) ∨ `d.at_commit == Some((f.commit, f.review))`; else 409 with the existing "The document or its source changed …" copy + detail `ui: verdict: commit does not hold the reviewed bundle` (comment). Record commit = `f.commit`. A shell/kernel disagreement mismatches the pair ⇒ refusal (fail-closed).
- D5 `ckc ui request --commit <c>` (fixture + oracle seam; 7 `verdict-*` cases): the filesystem tree stands for commit `<c>`: the page carries `<c>`; posted `<c>` ⇒ `at_commit = Some((<c>, tree derivation))`. Git-mode custody = the `git-*` carriers + `ui_socket`.
- D6 kept: HEAD-freshness 409, ledger CAS, Host/Origin/CSRF guards, lock protocol; `ckc check` re-derives bundle v2 at every nonempty `ace_commit` (Q2) ⇒ rows written under N2 grade with no check change. Scope limit: two commits holding the same bundle are indistinguishable to the server; custody = the recorded commit holds the reviewed bundle; an honest page posts its own commit.
- D7 (user choice): the posted commit must be HEAD or an ancestor of HEAD ⇒ a history rewrite between render and POST refuses (409) instead of recording a commit outside the branch.

## Predicates (acceptance)

- P1 page: git-mode document page `commit` = the rendered HEAD (ui_socket; `ui render` on the `git-*` carriers = the fixture commit id); filesystem-mode page = empty value (`ui check` = worktree mode, plain fixture trees); `ui request --commit <c>` page = `<c>`.
- P2 spec + proof: Prepared ⇒ record commit == `f.commit` ∧ ((`s.commit` empty ∧ `f.commit` empty) ∨ `d.at_commit == Some((f.commit, f.review))`); `ui_post_outcome` + `ui_posted_commit` + `ui_render_document` bindings exec == spec; `ui_post_sound`, `ui_document_sound`, `ui_copy_ok` re-verified under `--no-cheating`; generated K5 files regenerated (`replay` identical for untouched generators).
- P3 row probe (ui_socket): fixture commit → A; GET page; commit B touching no guideline file; POST the page's own fields → 303; appended row ace_commit == A ≠ B. Red on the base binary (`CKC_UI_TEST_BIN`).
- P4 forgery (ui_socket; each: status + guidelines inventory byte-identical + no `.adjudication.tsv.*` left): hex40 naming no object → 409; an existing commit whose bundle for the document differs from the posted digest → 409; malformed (`ABC`, 39 hex, uppercase) → 400; empty in git mode → 409; (D7) a non-ancestor commit holding the same bundle → 409.
- P5 fixtures (`ckc ui request`, `tests/ui`): missing `commit` → 400 `missing field commit`; duplicate → 400; malformed → 400 `invalid commit`; filesystem mode + empty → 303 (row ace_commit empty); filesystem mode + nonempty commit without `--commit` → 409; `--commit c0` + posted c0 → 303 naming c0; `--commit c0` + posted other → 409.
- P6 regressions: every existing ui_socket, ui_fixtures, ui_lock assertion holds, modulo P7.
- P7 re-pin census (AM6 guard), split by verb: `ui render`/`ui check`/`ui request GET` document-page goldens differ from their base bytes by exactly the inserted hidden input (value = fixture commit id on the git carriers, `--commit` value, else empty); the form-shaped `ui request POST` bodies (78 of the 115 POST rows: 5..=32 pairs; the other 37 = missing-body, hex-body, empty, one-pair and 33-pair probes, whose first refusal stays unchanged without the field) gain exactly `&commit=<v>` (git carrier = fixture HEAD, `--commit` cases = that value, else empty); a script over the diff proves no other golden byte moved; every touched file listed.
- P8 docs + state: REFERENCE § Reviewer interface custody paragraph (the decision names the commit the page was rendered from; the server derives the bundle there); `.claude/rules/ui.md`; `.agent/spec.md` Decisions review-custody line; deferred row pruned; release manifest regenerated iff a release input changes.
