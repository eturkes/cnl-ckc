## Design

- D1 Dependency: `proptest` =1.12.0 as a dev-dependency of the crates whose suites hold properties (`ckc`), default features off + `std` alone (1.12.0's `std` = panic capture during shrinking + `rand/std`, `rand/sys_rng`, `regex-syntax`, `num-traits/std`: no smaller set keeps std strategies; `fork`, `timeout`, `bit-set` off); its resolved dev closure (13 crates: autocfg, bitflags, chacha20, core_detect, getrandom, num-traits, proptest, r-efi, rand, rand_core, rand_xorshift, regex-syntax, unarray) vendored + on `rust/trust/deps-allowlist.tsv`, every license passing `just deny`.
- D2 One config module (`rust/ckc/tests/support/prop.rs`, `#[path = "support/prop.rs"] mod harness;` per suite): `config(cases)` spells every `Config` field — `RngSeed::Fixed(SEED)`, `RngAlgorithm::ChaCha`, `failure_persistence: None`, `max_shrink_time: 0`, `max_shrink_iters: MAX_SHRINK_ITERS`, the reject + regen limits, `max_default_size_range` 100, `verbose` 0 — because `..Config::default()` takes every unlisted field from `PROPTEST_*` (`fork` + `timeout` exist only under their features); `check(cases, strategy, test)` = the sole entry, because proptest's own macro re-applies `PROPTEST_*` over any config it is given (`contextualize_config`); default collection sizes (`SizeRange::default`) read `PROPTEST_MAX_DEFAULT_SIZE_RANGE` outside any config ⇒ `check` refuses to run while it is set; SEED + MAX_SHRINK_ITERS = committed constants; the failure report = proptest's (`Test failed: …` + `minimal failing input: …`) + the seed + case count, panicking at the suite's call site.
- D3 Regressions: no persistence files; each shrunk counterexample a suite ever reports → a named example test (`CLAUDE.md`: example tests pin every shrunk counterexample).
- D4 Law: `.claude/rules/rust.md` names the module, the seed + bound, `check` as the entry, the bypass scan (no suite spells the proptest macro, `Config::default`, `Config::with_*`, `ProptestConfig`, `TestRunner::default|deterministic` or `contextualize_config`; planted text fires it), the planted controls (P1–P3) + their firing, so later suites (MC's tester first) import the module instead of building a Config.

## Predicates

- P1 Determinism: a property suite run twice yields byte-equal case logs (the first 64 generated inputs written by a probe test) + verdicts; the same with `PROPTEST_RNG_SEED`, `PROPTEST_CASES` + `PROPTEST_RNG_ALGORITHM` set to other values (environment ignored).
- P2 Shrink: a planted predicate defect (a test-only predicate wrong on every vector holding an element ≥ 7) → the property fails and its report holds the shrunk minimal counterexample (`[7]`), pinned by an assertion over the captured failure.
- P3 Bound: shrinking stops within the committed iteration bound (no time-based budget: `max_shrink_time` = 0).
- P4 Dependencies: `just deny` + the allowlist check (`ckc trust-audit`) green with the new dev closure; a non-test build's dependency graph unchanged (`cargo tree -e normal` before = after).
- P5 Gate: the harness's suite runs inside `just test`; its wall time in the step ledger.
