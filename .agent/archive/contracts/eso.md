## Design

- D1 waiting (engine.rs): only an operator goal waits. `waits(g, later)` ⇔ `g = Lit(guideline_operator(O, X, Op), d)` (functor `guideline_operator`, arity 3) with `X` a variable and `run_binds(later, X)`; `O`, `Op` and `d` are unconstrained (a variable `O`, a variable `Op` and depth 0 all still wait); a compound `X` (even one holding variables) never waits. `run_binds(gs, X)` ⇔ some goal of the front run of `gs` binds `X`; front run = the leading goals `Lit(t, _)` whose term `t` is compound and not `\+`/1 (exact functor + arity; `,`/2 conjunctions included, every other compound — `\+`/2, `,`/3 too — a predicate literal); a `\+`/1 goal, a naf cut marker or a non-compound goal ends it. A run goal binds `X` ⇔ `binds(t, X)`: for `t = ','(A, B)`, `binds(A, X) ∨ binds(B, X)` (recursive look-through, including leaves after a `\+`/1 leaf inside the conjunction); for any other compound `t`, it has a first argument and that argument equals `X` syntactically (a zero-argument compound binds nothing) (a variable first argument = the same variable; occurrence elsewhere, inside a compound first argument or unifiability does not count); a non-compound `t` binds nothing.
- D2 selection (engine.rs): `selected(stack)` = 0 unless `stack.len() > 1` and `stack[0]` waits on `stack[1..]`, then 1 + `selected(stack[1..])` (so `selected([]) = 0`). Waiting is decided before any depth check. Structural consequences (the spec comment states them): every skipped goal is a waiting operator goal; a waiting goal's successor is a run goal, so the selection never passes a `\+`/1 goal or a naf cut — each reaches the front only after every goal left of it, and every goal those spawned, has run; a selected `\+`/1 or naf cut has k = 0; for k > 0 the selected goal is a predicate literal or a conjunction. Semantic scope: for clauses satisfying the compiler's safety (`emit.rs` `head_safe` + `naf_safe(c, doms, 0, {})`) over ground facts — every certified document — a negation's outer variables are ground when it is called and its box-local variables stay fresh, in both orders, so each negation gets the instance leftmost order gives it up to the renaming of its locals, and where both orders' search trees are finite they yield the same answers; whether a search terminates, trips a bound or which proof comes first follows the new order (consultant-4 `safe-ground-naf-cycle`: a safe ground program whose leftmost search loops forever while the new order fails finitely and answers). A v1 file with an unsafe negation (grammar-accepted, never certified) can reach a negation with more bindings than leftmost order gives it and answer differently (consultant-4 probe, P4 j). Not machine-verified: the theorems (P2) bind the new machine, not its equivalence to the old one.
- D3 step + call (engine.rs): an empty stack is handled first (unchanged). Else `k = selected(c.stack)`, `pre = c.stack.take(k)`, `rest = c.stack.skip(k + 1)`. The selected goal's depth is checked: depth 0 → pruned fail. Conjunction → `pre + [A, B] + rest` (one transition). `\+`/1 and naf cut → the front branches as today (k = 0). Predicate literal → `call(db, c, name, args, d, pre, rest, c.ci)` with `UState.stack = pre + body_goals(..) + rest` (the head's bindings reach `pre`, the body and `rest`); the choicepoint keeps the whole pre-step stack + `ci = m + 1`, and a resume recomputes the same k from that stack; `Cfg.ci` = the clause index the selected goal resumes from. Selection is recomputed after every transition: a waiting goal whose context the witness's head left unbound keeps waiting on the new run, or runs unbound when no witness is left.
- D4 trace machine (trace.rs): `tstep` + `tcall` mirror D3 over `tselected(stack) = selected(erase(stack))` (erase = drop paths); a body goal's path stays its body index; a conjunction split keeps the conjunction's path for both parts. Answer mode keeps one question goal (a conjunction split costs one transition each); trace mode keeps `roots_cfg(conj_leaves(goal))` (one root per leaf, path `[i]`, no split charge).
- D5 unchanged: R8 bounds; the R15 cost model (below); `naf_safe` (evaluated at the front); recursion-check = leftmost body goal (portable-product guard, not a termination analysis of the new order; REFERENCE documents the gap); answer + trace artifact grammar; every `contract.rs` binding + the `k3_sound` statement; compiled Prolog body order (a standard Prolog engine keeps leftmost search). Replay (`aggregate-check` obligations) runs on the same machine, so its search order changes with answers + traces. engine.rs gains schema vocabulary (`guideline_operator`); Decisions neutrality covers source language, not schema predicates.

## Cost model (R15; tester authority, unchanged by this unit)

- Answer mode (`engine.rs` `run`, `solve`): stack starts `[Lit(question, 100)]`; every `step` = one transition of the 100000 budget: a predicate dispatch (call or redo, its whole clause scan + head unification included; a dispatch that fails and resumes the newest choicepoint = one transition), a conjunction split, a negation entry, a naf cut, a depth-0 prune, a solution record (wh mode), the empty-stack step that ends a yes/no search with `yes` (it needs fuel ≥ 1 too). Body goals run at depth d − 1; a negation's inner goal at d − 1. Fuel 0 → `End { complete: false }` = `indeterminate(limit)`; exhaustion with any prune → `indeterminate(limit)`; without → `no(finite_failure)` (yes/no) or `solutions` (wh, `sort_unique`, a nonground row → `proof, nonground_solution` first). Yes/no stops at the first solution (`yes`).
- Trace mode (`trace.rs` `trun`, `prove_row`, `trace_rows`): per row, roots = the question's leaves (answer variables bound to the row's values), each at depth 1000; every `tstep` = one transition of the row's 100000 budget, a terminal `Sol`/`Done`/`Limit` included; a negation's inner goal gets a fresh depth 1000; a row's charge to the whole run = its consumed transitions + one per materialized clause node, against 1000000.
- Replay (`replay.rs` `head_proved`): each obligation head = `[Lit(head, 4000)]`, budget 1000000, yes/no mode.
