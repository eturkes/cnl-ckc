# Deferral queue

Off-path improvements + ruled deferrals, one row each: `- <what> (<source>). Accept: <check>`. A row enters while its evidence is fresh and leaves in the commit that meets its check; a skipped, xfailed, deleted or tier-demoted case enters here with user approval (`CLAUDE.md` `Engineering`). Unfinished units stay in `.agent/spec.md` `Tasks`.

- Kani engine + trace harnesses (`rust/ckc-kani-harness` `engine_answer_tiny`, `reader_trace_check_small`; outside the `just kani` recipe) — waits on its re-open trigger (user ruling). Measured (Kani 0.67.0, CBMC 6.8.0): bypassing the parser does not remove the exhaustion — a typed below-parser seam answering over 2 facts rc 124 (symbolic goal 1500 s, concrete 900 s), one concrete `unify` f(a)=f(X) rc 124 at 600 s (BTree collections as shipped, and again with Vec stand-ins), whole-file `v1_answer` 5 runs rc 124 at 1200 s. During symex, values read back from the kernel's term arena (var key, node tag, `maximum`) stay symbolic on concrete input: a loop counted by one unwinds to the bound 7, while `Vec<usize>` + `Vec<Option<usize>>` controls unwind exactly; padded structs and enums with padding in heap `Vec`s lose precision the same way, padding-free structs and tuples fold. Inference (not measured): that representation-level loss is the main obstruction, so the engine path needs padding-free or typed storage under `cfg(kani)`, contracts that avoid the reads, or another checker. Kani 0.68.0 (CBMC 6.11.0) = the first trigger: `engine_answer_tiny` rc 124 at 1200 s in 2 runs (load average ≈9 and ≈1.5). Re-open trigger: the next `rust/kani.lock` bump → rerun `engine_answer_tiny` (cap 1200 s); fund the unit only if that run finishes. Accept: typed below-parser kernel seam + one engine harness and one trace harness green in `just kani`.
