Unit = `ckc ui serve [<port>] | render <out> | check | request <method> <path>`
replacing `tools/ui.py` (map-4 R4 = the byte-parity target: routes, POST law,
render outputs, committed-corpus reading). Behavioral reference = the legacy

## Tier

- kernel (`ckc-spec/src/ui.rs`, MAIN-authored): viewmodel from the committed
  corpus (K1/K4 bindings supply documents, coverage rows, bundles, ledger
  classes); HTML render = a pure function of the viewmodel (theorems: every
  visible text byte comes from the corpus, the copy registry or a digit
  string; HTML escaping total — `<`/`>`/`&`/`"`/`'` never appear unescaped
  in text/attribute positions; determinism = purity); copy registry = const
  data with the banned-token gate as a spec predicate; POST guard chain
  (Host, Origin, content type, six exact fields, verdict/reviewer/comment
  grammars, token, docid, subject digest = the fresh review bundle digest,
  ledger digest CAS) as an ordered first-refusal law; ledger candidate =
  seven-column row insertion by (docid, date) preserving older rows, byte
  exact; the candidate must satisfy `check.rs` `ledger` (+ classification).
- shell (enumerated, fixture-gated): loopback socket, HTTP request-line/
  header parsing subset (request text → method/path/headers/body given to
  the kernel), per-process random token, `git archive HEAD guidelines` intake
  (committed reading, live ledger overlay), mkstemp/fsync/flock/rename, CSP
  hash of the one fixed script, response headers (H5), render directory
  writes, `ui check` double-render byte compare (retained as a runtime
  probe beside the purity theorem), exit codes.

- R70 escaping + copy theorems replace the legacy AST string scan + runtime

- R73 escaping law = legacy `html.escape`: text nodes escape `&` `<` `>`

  `well_escaped` reads per position; byte parity governs the theorem's
  shape. The ≤~1.2K-line target yields to fidelity (alignment tokenization,
  palette/CSS/script bytes are render); the M5 spec audit adjudicates size.
- R76 (revised) copy law domain: the registry's code points are ASCII plus
  an ENUMERATED non-ASCII punctuation repertoire present in the emitted copy
  (em dash U+2014, middle dot U+00B7, `≥` U+2265, `§` U+00A7, … — the exact
  list transcribed from ui.py), all non-word for `\\b`; the banned-token
  predicates run in legacy order over that classification (ASCII word
  boundaries + repertoire = non-word) = exact Python `(?i)\\b` on the
  domain; the transcribed emoji intervals fire the legacy emoji violation
  (the red emoji fixture stays byte-exact); any other non-ASCII code point
  fails closed with a named domain violation (non-ASCII letters never occur
  in the registry or the 12 copy fixtures); no Unicode word table, no shell
  primitive; invented-acronym judgment stays an unmechanized design rule.
