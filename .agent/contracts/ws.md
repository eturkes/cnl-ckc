## Design

- D1 Reach: formula operands alone (da2 D1: a `$guideline_bound` item whose operand is a formula operand; a `some` amount `$guideline_amount`). Every other witness pair stays as today (anchored referents, box contexts, nt1 converted conditions outside formulas, scaled time, the supersession `Date − 1`); a `/6` time comparison cannot match an operand's unit fact in today's grammar, so time witnesses stay fixed.
- D2 Default w0 = da2 D4's witness in exact rational arithmetic: `some` → 1; `exactly N` → N; `geq N` → N, or 1 when N = 0; `leq N` → N, or −1 when N = 0; `greater N` → N + 1, or N + 2 when N + 1 = 0; `less N` → N − 1, or N − 2 when N − 1 = 0 (integer or canonical rational N; for an integer N = da2 D4's value; for a rational strict bound da2 D4 returned N itself, which its own condition refuses — no committed operand has one: D9).
- D3 Boundaries of an operand X: B = {X's own bound, when its condition states one} ∪ {Bound of every `guideline_satisfies(C, D, Op, Bound)` inside a NAF item of the variant that is relevant to X} ∪ {0}. Relevance = a finite existential join over a snapshot of the variant's witness facts fixed before the walk: X's count slot = an open labelled slot, every other operand's count slot = an open unlabelled slot; the item's semantic (non-built-in) goals are matched against those facts under one shared substitution (branch-local bindings, occurs check), built-ins ignored as tests during extraction; the comparison is relevant iff some match makes its D originate in X's labelled slot (a numeric equality with another fact's count is no origin). An irrelevant comparison contributes nothing (over-collection changes the first winner). Candidates = B ∪ {b − 1, b + 1 : b ∈ B} (exact rational arithmetic: `rational(N, D)` ± 1 = `rational(N ± D, D)`, canonical) ∪ {(b_i + b_{i+1}) / 2 : b_i < b_{i+1} consecutive in B by rational order}, kept iff X's own condition admits them (exactly → = N; geq → ≥ N; greater → > N; leq → ≤ N; less → < N; `some` → every value); order = w0 first, then rational ascending, canonical duplicates dropped.
- D4 Tuples: the distinct operand referents of the variant, once across all its formulas, in antecedent DRS order; a constructive lazy odometer (an index vector, the last operand varies fastest, carry to the left; no product allocated); no operand = one empty tuple. Per tuple, the chain nodes evaluate as da2 D4 (DA1 `arith_result`).
- D5 Winner = the first tuple t with Win(P, t) := ChainDefined(t) ∧ heads_proved(witness_db(Facts(t), P), Heads(t)): P = the document's exact clauses; Facts(t) + Heads(t) = da2 D4's obligation under t (facts = positive body goals minus built-ins, heads = bound heads); `witness_db` + `heads_proved` = the existing K2 replay relation (the facts as the reverse-ordered front, a fresh replay_depth/replay_inf budget per head; a positive proof found after a pruned branch counts, as in K2; NAF fail-closed). No new evaluator: the spec reuses its total constructive replay. P = every clause of the document, sentences after the formula included ⇒ emission is two-phase: all clauses first, then each formula variant's selection + payload over the finished P (spec + kernel); the fork's proof mode asserts the complete document before any candidate replay.
- D6 Outcomes (iff): no tuple derives every chain node ⇔ w0's chain fails ⇒ reject `formula_shape(witness, S)` (lemma: w0 is zero only at an operand forced to `exactly 0`, which every tuple shares; fixed zero literals are shared by every tuple; every other operand's w0 is nonzero; a chain fails only at a zero divisor ⇒ any chain-defined tuple implies w0's chain is defined); else the D5 winner when one exists; else the w0 tuple as fallback (w0 is in the searched product, so its replay failed under the same authoritative relation; the compile reports `underivable_obligation`, as today). First-error priority across formulas + every other reject + its order unchanged.
- D7 Completeness (stated + proved in the spec): fragment premise (decidable, conservative) = canonical ground bounds; a witness skeleton fixed except the operands' counts; every numeric constant that can meet an operand's count during the replay of P with Facts(t) — a numeric constant in a cardinality count position of any clause of P or of a non-operand witness fact, and the bound of every built-in whose input can bind to that count — belongs to B; the exact scalar chain defined. Theorem: under the premise, tuples in one product cell (per operand, a cell of the partition of the line by B) give the same bounded K2 replay — identical unification + built-in outcomes, hence the same search, budget use and Win verdict — so each nonempty cell is represented by a candidate (b, a midpoint, b_min − 1 or b_max + 1) and a winner exists whenever any rational tuple meets the operands' conditions, the chain + Win. Outside the premise the selection stays sound (a winner replays by construction), not complete. Win proves the heads (an alternative proof may discharge a head), never the selected variant's body; a composition's other guidelines stay the aggregate's.
- D8 Certification: the certified payload = the spec's (the D5 winner under K2). The fork selects with its own per-document replay as an untrusted producer, its NAF made fail-closed for selection (a depth cut inside a negation = no replay, as K2; consultant-13 round 2: today's fork replay is fail-open there while the native aggregate refuses, and both accept a positive proof found after a pruned branch); on a certified success its payload bytes = the spec's = certify-one's; a fork/K2 disagreement (control, order or fuel) = an explicit certification refusal (loud: an availability limitation, never silent divergence). For a fallback rule the projection succeeds with the fallback payload while the fork reports `underivable_obligation` + the native aggregate refuses. Selection = a constructive relation both implementations refine.
- D9 Committed products: every committed formula variant (15: s33-01 = 14, 10 with NAF items; s42-15 = 1) keeps w0 as its winner (consultant-13 census) ⇒ every committed payload, answer + trace byte-identical against the unit's base (the CHR pins for s33-01 + s42-15 included).
- D10 Docs: REFERENCE § Formulas in ACE (default-first numeric candidates, exact rational cells, replay-checked selection, fallback + undefined-chain reject, the completeness fragment, the composition boundary), `.claude/rules/compiler.md`, the compiler header.
