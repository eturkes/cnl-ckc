# cnl-ckc spec

## Intent

cnl-ckc compiles the natural language of published clinical guidelines into an executable knowledge base, through a layer that clinicians can audit. Each guideline passage becomes an Attempto Controlled English (ACE) document. Clinicians review each ACE document beside its source passage. The compiler turns each ACE document into plain Prolog that is portable across Prolog engines. This Prolog follows the schema that `docs/REFERENCE.md` specifies. The compiled output includes proof obligations, custody digests and committed demonstration queries. Each query carries its answers and proof traces. The project has three goals, in priority order:

1. An executable knowledge base that software can query and combine. A clinical decision support (CDS) system can later load the knowledge bases of several guidelines together. It can match them against the information of one patient, also when the patient has more than one condition, and give a clinician a recommended course of action. The knowledge base must therefore keep what this matching needs: the conditions of each recommendation, its timing and severity, the strength of each recommendation and the preference of one option over another. The project does not build the CDS system.

2. Clinician-auditable compilation. The project keeps the ACE and Prolog approach. A coverage plan (`docs/m7-gap-taxonomy.md`) tracks the semantic gaps of this approach. The plan records each gap class as covered or open. Example classes are timing, dosing arithmetic, probability and preference strength. Each class is its own piece of work. The compiler is not fixed. Extensions of ACE constructs, further schema revisions and companion or alternative targets stay open for evaluation. One such target is ProbLog, for content that carries uncertainty. Before the knowledge base is distributed, clinicians use the reviewer interface to check that each ACE document is faithful to its source passage. This audit must be as easy as possible for them. This fidelity stays permanently outside formal verification.

3. Formal verification of the compilation and of every other logical step that the software's function depends on. The verification follows the verified-kernel pattern. A small formal specification is the part that humans read. AI writes the implementation and its proofs, and no human inspects either. A pinned deterministic checker and an escape-hatch audit complete the pattern. The layer that humans must audit stays as small as possible. Soundness for software as a medical device (SaMD) sets the boundary between verified steps and trusted software. Verification covers the logical steps from ACE to clauses to answers. It also covers the custody chain that binds the source, the ACE, the clauses, the review verdicts and the export. Git, the filesystem, subprocesses, the clock, pinned mature dependencies and process or legal validators are trusted software. Fixture gates check this trusted software. The Prolog stack keeps one role: emission from ACE through the discourse representation structure (DRS) to clauses. This role keeps verification that humans can review. Translation validation certifies every compiled document and question against the formal specification.

The scope stays minimal: fetch, normalize to ACE, compile, review locally and export deterministically. The project has no serving layer and uses no large language model at run time. Everything that a human must read is ACE, the formal specification or a named small Prolog closure. The closure stays on this list until it is certified.

## Decisions

- Product = KB artifacts (`guidelines/*/{ace,pl,align}` + lexicons + vocabulary tables + ledgers + committed queries with answers + traces); compiled Prolog = the public interface (the schema of REFERENCE § Compiled Prolog schema); sole in-repo consumer = the loopback reviewer UI. Feature scope final; new scope only by explicit user direction (M5–M7).
- Language boundary: Prolog owns ACE→knowledge emission (`ace_to_pl.pl` compile/proof/question modes) + stays the portable KB product; hand-authored Prolog confined to that closure. Rust owns the bounded in-repo consumer (read/write of the schema, engine, replay, answers, traces, trace check), verification, custody + all non-Prolog tooling — never a general-purpose Prolog runtime, never domain knowledge. The native chain (`just check`, `just certify`) is the sole authority; the retired pre-cutover toolchain lives at tag `legacy`.
- Consumption→Rust affirmed: no mature Prolog verifier ⇒ that role gains human-reviewable verification only by migration; emission stays Prolog, certified per document + question by translation validation (M6).
- Verification line (grading = `archive/rust-rewrite-plan.md` § Verification line): human-read `ckc-spec` + AI-authored `ckc-kernel` (never human-reviewed; agents read + edit it) + pinned Verus `--no-cheating` + `ckc trust-audit`. Theorems = KB semantics (K1–K3), custody chain source↔ACE↔clauses↔verdicts↔export (K4 core), render fidelity incl. Word meanings + reading words + POST guard/ledger CAS (K5 core), M6 emission correspondence. Shell tier (enumerated, fixture-gated, no theorems) = the Intent's trusted software + sockets, HTTP, archive assembly. Every spec line traces to a soundness/custody claim; claim = "machine-verified against the committed spec under a pinned verifier TCB". Fallback (Verus blocker, proof:impl >5×, solver brittleness) → Creusot or a narrowed kernel.
- Search order (user rulings; contract `eso`): the in-repo engine (answers, traces, replay) runs the leftmost goal, except that a `guideline_operator` goal whose inner context is unbound waits while a later goal of its run (predicate literals other than the comparison built-ins, which bind nothing, + conjunctions, up to a negation, a nonground comparison built-in or a naf cut) names that context; the leftmost goal that does not wait resolves in place, so a box is checked right after its content's head unification; a question's goals follow the same rule. Compiled Prolog keeps its body order (a standard Prolog engine searches leftmost); recursion-check stays leftmost. Where both orders' searches end, safe clauses (every certified document) keep leftmost answer sets; termination, bound trips + first proofs follow the new order; an unsafe negation can answer differently (argued in contract `eso` D2, not machine-verified).
- Review custody (user rulings): a ledger row's `ace_commit` = the commit the reviewer viewed = the commit the page was rendered from. The page posts it back; the UI records the posted commit only once review bundle v2 derived there equals the reviewed digest and it is HEAD or an ancestor of HEAD (`.claude/rules/ui.md`) ⇒ custody = the recorded commit holds the reviewed bundle (a hand-made POST can name another such commit); `ckc check` re-derives review bundle v2 there for every nonempty row.
- Spine: M5 closed (IMPLEMENT); corpus rounds = MAINTAIN requests; each M7 gap class = its own request, phase per `CLAUDE.md` `Routing` (user rulings; `.agent/deferred.md`). Per unit: contract of testable predicates + tier before code (`.agent/contracts/<unit>.md`, archived at close); corpus + query artifacts byte-stable except ruled re-pins. M5 rulings (`archive/contracts/m5u*.md`; m5u2 R1–R30 = codec + engine law, cited in code) bind the code they shaped.
- Schema evolution (user ruling, until the first publication): one evolving schema, identifier `1`, for every guideline + question: no frozen older version, no version selector, no mixed-version reject (any guidelines combine in one composition); each schema revision re-derives the whole corpus + every fixture; strict versioning + provenance start at the first publication. Predicates + semantics = REFERENCE § Compiled Prolog schema; each revision = its own unit contract + user rulings (`archive/contracts/`; the compiler header names them). A statement ACE cannot express ⇒ region `uncovered(inexpressible: <reason>)`, counted by the coverage meter (user ruling). Gap classes, their status + ruled dispositions = `docs/m7-gap-taxonomy.md`; each open class (ACE extension, a schema revision, companion targets such as ProbLog) = its own user-directed request, not presumed.
- Strength class (user rulings; Intent goal 1 first): grade record = dimension + common value (strength `strong|conditional`, evidence `high|moderate|low|very_low`) + the source label referent, attached to the recommendation referent of a root-fact grade sentence; ≤1 grade per dimension per document, applying to every statement of the document (statement contexts + the referent share the docid); the per-guideline table maps each grade noun (an authoring ruling the guideline page shows). Preference = a table-named alternative preposition (CDC: `instead-of`, never `over`) → (event, preferred, alternative) + a table-named preference adjective on a copula → (event, preferred, `none`); data only (no ranking, no prohibition of the alternative). Hedges = qualifier record `guideline_qualifier(Context, Event, Class, Word)` on the action it qualifies, every class typed (usuality, ideality, focus, manner, force, possibility, applicability); the per-guideline table maps each qualifier word to its class (a reclassification = a table row); a `might` statement re-authored to restore its dropped proposition. Corpus: every expressible statement re-authored; a generic preference is a patient-conditioned rule. Review = the Word meanings table + the reading line (Decisions `Review UI`); qualifier kind words How often, Best case, Emphasis, Manner, Strength of wording, Possibility, Condition of use.
- Authoring principle (user rulings, every knowledge type): type everything the schema can carry; a hard statement gets MAIN's best attempt at typing it, its interpretation recorded in `audit/projection-notes.tsv` like any other; the normal clinician review of the ACE + the word meanings (Decisions `Review UI`) catches a wrong typing — no judgment note, flag or marker reaches clinicians; a deliberately recorded loss is no authoring option; a meaning without any schema carrier = a gap class (`docs/m7-gap-taxonomy.md`), never invented data (no invented endpoint or value).
- Numeric threshold (user rulings; contract `archive/contracts/nt1.md`): a condition's `exactly|at least|more than|at most|less than N` matches by value-set inclusion over a dense domain with integer endpoints (a plain number states at least that many; a plain-number condition keeps exact structural matching); time units compare by fixed ratios within seconds–weeks and within months–years, a day never meets a month; each passage keeps its source unit; a bare calendar adverb (`daily`) carries no bound; no review table (Decisions `Review UI`); `guidelines/schema.pl` = the spec-printed definition, shipped in every archive with the load line naming it first.
- Prohibitions (user ruling at the strength-phase close; Intent goal 1): a source prohibition = SHOULD over a negation — `it is recommended that … does not …` (`If there is an X then …` for a universal; `If … and there is an X then …` inside a rule) — because `X should not V` compiles to ¬SHOULD (no obligation), which a consumer matching prohibitions never sees; `should not` stays only where the source denies an obligation.
- Condition scope (user rulings; contracts `archive/contracts/cs0.md`, `cs1.md`): a guideline opts in with the table pair `scope <noun> <key>` + `exclusion <verb> scope`; an exclusion = `If <condition> then it is false that a <noun> <verb>s …` → record `guideline_exclusion(Key) :- <condition>`; the guard `\+ guideline_exclusion(Key)` gates every should/must/may edge clause of a scoped document (edges only: whole-rule guards need typed stratification, deferred) and recursion-check rejects a body naming a guarded edge; exclusions only — population + audience statements stay data, per-recommendation conditions live in the rules they govern (no uniform inclusion gate, deferred); a composition = one patient; bounded negation fails closed (a cut negation → `indeterminate(limit)`, replay → `obligation_failed`); authoring: a condition meaning no record of X (contraindications, documented prerequisites, unless clauses) → `does not provably`, an observed negative finding stays classical, each change in the projection notes; the whole census is re-authored (CS2a, CS2b); no review surface: an exclusion reads in its ACE sentence (CS1b retired by the `Review UI` ruling, kept at tags `archive/cs1b`, `archive/cs1b-general-3`).
- Dose arithmetic (user rulings at the DA orientation, AskUserQuestion ×3; contracts `.agent/contracts/da1.md`, `da2.md`): surface = an ACE formula in a rule consequent, `… includes some <unit noun> Y and Y = <expr>` (`*`, `/` over antecedent quantities + numeric literals), with two cnl-ckc ACE extensions, both limited to formulas (user pick after consultant-1's F5 named them: neither is APE's reading nor follows from nt1): (1) a unit-noun amount in a formula stands for its count; (2) `some` before it sets no bound (APE alone reads `some` + plural as at least 2); the alternatives `at least 0` (one extension, odd English) and numeric values (`X >= 50` conditions, value in the article's count slot, re-authored thresholds) were declined; numbers = exact rationals: an integer or the canonical `rational(N, D)` (D ≥ 2, gcd(|N|, D) = 1), never a float; operations × and ÷; bounds propagate as value sets (`exactly` = a point; `eq`, `geq`, `greater`, `leq`, `less` = rays): a point or ray image derives, a whole-line image, a divisor that is not exact or is 0, `about` and `na` derive nothing; the comparison built-ins accept rationals; corpus = the CDC conversion table as evidence + one document of conversion rules, S33-01 restates it, a census re-authors every class statement the formula carries; demonstration = a `tests/queries` fixture with a patient world, no guideline query (an example `opioid-dosage` fact would surface in CDS answers); the total across a patient's opioids (a sum over loaded facts) stays a recorded gap.
- Review UI (user rulings at the condition-scope close + the `UI revert` request; contract `archive/contracts/ur.md`): the review pages keep the sections of 53186717 — document page: passage, ACE, decision form, compiled Prolog, navigation; guideline page: status, documents, passages without ACE — with the N23 separators + tab title; no as-compiled tables and none of the four word tables: every typed fact reads in the ACE. The vocabulary table's meanings show once per guideline in one merged Word meanings table after Status (their audit place) + on a click, tap or keyboard activation (Tab, Enter/Space) of a reading word: grade + evidence nouns, qualifier words, preference + alternative words anywhere, the scope pair only inside the sentences the compiler read as exclusions (the verb's lemma or its regular third-person spelling); never time words. Each reading word = a button styled as its word with a thin link-blue underline, thicker while its reading shows; the reading fills one reserved line under the ACE box as a table-level claim (`In this guideline, the compiler reads X as Y.`), a short hint while nothing is selected; a second activation or Escape restores the hint; alignment highlights stay click/tap (keyboard access to them unruled). Readings: `a strong|conditional recommendation`, `<value> certainty of the evidence`, `the preferred option`, `the alternative to the preferred option`, `a qualifier: <kind word>`, `every recommendation of this guideline`, `the verb of a scope exclusion: when its condition holds, no recommendation of this guideline applies to the patient`.
- Publication scope (user ruling): the first publication covers the CDC guideline alone; until then the schema + the whole corpus re-derive freely (Schema evolution); after it, schema evolution needs an approach that scales with the corpus.
- Corpus: knowledge-only fixture-free ACE compiled under the schema (an unused `vocabulary.tsv` row stays legal: user ruling, no liveness check); obligations discharged per document + aggregate; answers/traces = machine-derived demonstrations. Neutrality: nothing source-language-specific in tooling/schemas/ledgers; domain rules live in corpus data.
- Deps minimal + enumerated (`rust/trust/deps-allowlist.tsv`: mature, easily reasoned about, dangerous to hand-write); verifier pinned (`rust/verus.lock`), bumped to every stable Verus release (user ruling); own `=` pins follow upstream: `just outdated` reports a crate that only members' `=` requirements hold as drift (user ruling).
- Review: check set fixed before reading; every row adjudicated (finding → fixed in its unit + one re-review round on its acceptance check, or ruled; register entries → fixed or queued in `.agent/deferred.md`). Verdict tables live in each reviewer's scratch deliverable; the unit's commit body records every reviewer (name, role, verdict) + each finding's disposition. `.agent/review.md` = the committed ledger for rows still open when a session ends (header only = none open; closed ledgers → `.agent/archive/`).
