# SB1 seams (MAIN; fixed before builders start; contract `sb`)

All text UTF-8, LF; ground terms in the canonical v1 writer's spelling (`ckc_kernel::contract` reader/writer; the fork's `render_term_line`).

## Composition (generator → producer, checker, harness)
- `<dir>/composition.tsv`: one path per line = load order (documents, then the patient world); one canonical document per file (generated copies under `copies/<NNNN>/<docid>.pl`, never concatenated: each file passes `contract::v1_check` on its own); a relative path resolves against the repository root every tool takes as an explicit argument (`--root`), never the working directory. `guidelines/schema.pl` is not listed (built-ins load engine-side) but is pinned by the identity below. Comment lines `#`.
- Composition identity = sha256 over the framed records `schema\0<len>\0<sha256(guidelines/schema.pl)>\n`, then per listed file in order `file\0<path as listed>\0<len>\0<sha256(bytes)>\n` (len = decimal byte count).
- `<dir>/manifest.tsv`: `key\tvalue` rows — family, scale point, G, k, transform version, generator commit, input sha256 per source document, seed, patient profile id, expected-output sha256 (q-all), annex param ids.
- `<dir>/queries/q-all.txt` = the one line `sb1-q-all 0`; its answer = one line per should/must/may context `box(C,O,[P1,…,Pn]).` (Pi = every model literal whose first argument is C, standard order; a nested box = its own line), lines in standard order of terms, canonical spelling. `q-one.pl.in` + `q-patient.pl.in` (`.in`: tracked Prolog outside the inventory) = `ckc v1` question files (canonical query wrapper; answers in the answers-file format).

## Producer (`prototype/sb1/producer.prolog`, SWI 10.0.2)
- `swipl -q -f none -F none -s prototype/sb1/producer.prolog -g sb1_main -t 'halt(9)' -- --root <repo> <composition.tsv> <out-dir>` (`--root` required, as for every tool).
- Slice mode = the same command with `--root <repo> --slice <composition-identity> <slice.pl.in> <out-dir>`. Each slice record = `sb1_clause(<document-index>,<clause-ordinal>,(<clause>)).`; ids are those of the original composition, not a renumbering. The orchestrator binds the identity to its prepared knowledge base + freshly admitted patient. The producer loads the schema + exactly those records, including an empty selection; it reads no original composition files. Envelope + model format stay unchanged.
- Full-composition mode loads `guidelines/schema.pl` + the composition under the REFERENCE § Loading recipe (tabling), evaluates, writes `<out-dir>/model.txt` (every model fact incl. metadata facts, one per line, standard order of terms, deduplicated) + `<out-dir>/certificate.txt` + `<out-dir>/producer-phases.tsv` (`phase\tseconds\tcpu` rows: load, eval, certificate, write; immutable once written). Failure = rc ≠ 0 + one stderr line naming the stage (load | eval | certificate | write | resource).
- Certificate envelope: line 1 `sb1-certificate 1`; line 2 `composition <composition identity>`; then one line per model fact: `<model-line>\t<clause-id>\t<valuation>\t<level>`; model-line = its 1-based index in model.txt (producer order = 1, 2, …; checker accepts any order with exact coverage); clause-id = `<document index>:<clause ordinal>` (document index 1-based in composition.tsv order; ordinal 1-based over every non-directive term of the file, schema-version + metadata facts included; patient documents included); valuation = the canonical term `[=(v1,T1),=(v2,T2),…]`, keys `v1, v2, …` dense over the clause's non-local variables in whole-clause first-occurrence order (negation locals excluded), spelled by the canonical v1 writer; valuation cells = period-free canonical terms; model.txt lines = canonical terms ending `.`; level = a natural number: facts of the composition (metadata + patient facts included) = 0; an instance without positive body facts ≥ 1; otherwise > every positive body fact's level. The content stays one supporting clause instance + ground valuation + level per fact; only its repeated fact text becomes a reference.
- Level algorithm (D7): ground every clause body against the model (candidate instances, NAF + built-ins evaluated against the fixed model), then an agenda: facts of the composition start at 0; an instance becomes ready once all its positive body facts hold levels and gives its head 1 + max(those levels) (max of none = 0); the lowest ready level wins, so a founded support is chosen whenever one exists; facts left without a founded instance = an unfounded residual (reported; the run fails).

## Checker (`prototype/sb1/checker/`, Rust prototype)
- `checker --root <repo> <composition.tsv> <model.txt> <certificate.txt> [<query.pl>]` → rc 0 = accepted (stdout = the query's answers, or `accepted <n> facts`), rc 1 = refused (stderr one line: `refused <stage> <first failing claim>`, stage ∈ envelope | identity | claim | closure), rc 2 = usage / parse / I/O (stderr names it); writes `checker-phases.tsv` beside the model (`load` = parse of the composition, reported apart; `decode` = certificate + model parsing, charged; `admission`, `index`, `support`, `closure`, `answers`: seconds + CPU) + `checker-counters.tsv` (logical counters apart from runtime counters, contract D6). Levels: any natural numbers satisfying the strict decrease are accepted. `accepted` = a prototype test result, never the public claim of Decisions Patient answers.
- Checks: envelope + composition identity; model-line references in range, every model fact claimed once; any CR byte in model.txt rejects as a parse failure before line normalization (certificate CR bytes still refuse at envelope); model + valuation spelling checked during parsing against the canonical writer's token forms (atom spellings cached within the run); legacy envelope `sb1-certificate 0` (fact text in the first claim cell) remains accepted for differential controls; each claim's instance (clause head = fact under the valuation, built-ins hold, every NAF absent from the model with locals existential, positive body facts in the model with lower levels); closure over every enabled instance of every clause (T_M(M) ⊆ M); answers projected, canonically sorted + deduplicated.

### Prepared orchestrator
- `checker orchestrate [--provider all|static] [--slice-ids <file>] [--producer <file>] [--swipl <file>] --root <repo> <composition.tsv> <out-dir> <query>` = one owner process + its SWI child. Sibling `manifest.tsv` key `patient_documents` = the positive count of trailing patient documents (intake projections + patient world); absent key/file defaults to 1. The whole suffix stays outside the reusable knowledge base, its admission/hook/indices and identity prefix. Every call freshly reads/admit-checks all suffix files as facts, frames them in original order and materializes all their facts independently of knowledge selection. Invalid/duplicate/out-of-composition counts reject. The standalone checker remains the whole-model regression path.
- Load = source parse + canonical/shape/safety admission + typed-analysis hook + head indices + serialized source clauses + incremental identity prefix; built once in `PreparedProgram`. Per call = fresh patient bytes + admission + identity, query parse + slice, slice serialization, SWI load/eval/certificate/write, model + envelope decode, slice-model indices, support + closure over every selected whole clause, answer sort/dedup/serialization. Prepared calls retain no model or patient state between calls. The CLI holds the prepared heap through process exit (OS reclamation); normal library callers own its lifetime. Loaded RSS stays charged through exit. Score ends at the flushed+closed complete answer sink; subsequent prepared-program teardown is its own load-side lifecycle phase (contract D1), never scored.
- Provider seam = `SliceProvider::prepare(&[ClauseSource])` at load, then `select(patient_sources, query_bytes) -> Vec<ClauseId>` per call; each source carries its original `(document, ordinal)` + clause text. Selected knowledge ids cross into materialization/checking; all patient-fact ids are added separately. Invalid/duplicate supplied ids reject. A provider is responsible for conservative selection; this prototype does not verify an external selection's relevance theorem. The default static provider narrows conjunctive calls against head patterns (rigid constants + constructor prefixes), follows positive + NAF calls transitively, and closes every selected whole clause's body rather than assuming query bindings restrict that clause. q-all + model-only selection = all, preserving every context payload. `--slice-ids` = diagnostic injection, never a soundness claim about arbitrary selections.
- `all` = the regression provider. Built-in providers leave the typed-analysis hook empty; `load_analysis` still includes source serialization and `typed_analysis_hook=0` is distinct from an integrated admission. MAIN plugs the typed provider into the same prepared interface before graded admission.
- `orchestrator-phases.tsv`: `phase\tseconds\tcpu\tstart_seconds\tkind`; ordered names = load_parse, load_admission, load_analysis, load_index (`kind=load`), patient, slice, materialize, producer, decode, index, support, closure, answers (`kind=scored`). Offsets = exclusive owner-process wall intervals; producer owns the complete child interval, whose own `producer-phases.tsv` is diagnostic and is never summed again. CPU in owner rows = owner thread CPU; the outer harness records owner + waited-child CPU. Every gap before the complete sink stays scored. Post-sink exit/reclaim and controller cleanup are reported as teardown; the sampler and whole-invocation deadline continue through them.
- Diagnostic `SB1_STAGE_TRACE=1` adds `orchestrator-trace.tsv` (event, owner-relative wall ns, absolute owner-thread CPU ns, pid) + `harness-stage-trace.tsv` (role/event, controller-relative wall ns, parent CPU ticks, optional child identity/state/own+waited CPU ticks). It marks read/admission/identity/slice/SWI/check/output/rollback and parent exit/reap/publication. Origins differ; child CPU is comparable to parent-observed child own ticks only within `CLK_TCK` quantization. No interval reclassification, deadline or RSS-policy change; trace-on runs include their instrumentation cost.
- `selected-clauses.tsv` = one original `document:ordinal` per line, original composition order. Other counters use the checker format. Direct CLI success = rc 0 + answers alone on stdout; benchmark mode (`CKC_BENCH_SINK=closed-file-v1`) writes the closed answer file + marker instead; refusal = rc 1; parse/I/O = rc 2; producer failure = rc 3 (`indeterminate`), never partial answers. The harness owns the whole-invocation deadline + caps and reaps the owner's entire process tree.

## Generator (`ckc bench gen`)
- `ckc bench gen <F1a|F1b|F2|…> <1|2|4|10|100> --root <repo> --patient <compiled .pl> --out <rust/target/bench/…> [--documents <dir>] [--annex <dir>] [--queries <dir>] [--expected <file>] [--seed <u64>]`; parses documents with a shell-side reader over the canonical v1 text, validated by `contract::v1_check` + a byte-identical re-render (no kernel API change); missing frozen queries = a reported missing input, never invented.

## Harness (`ckc bench run`)
- `ckc bench run <composition-dir> (--producer <cmd> --checker <cmd> | --orchestrator <cmd>) --query <q> --blocks <n> --out <dir>`: separate regression processes or one owner with a SWI child. Commands are mutually exclusive. The caller holds `heavy` under D6. Both modes keep the exclusive outer interval ledger, process-tree RSS sampler, caps, paired plan + outcome matrix.
- Orchestrator command receives `--root <repo> <composition.tsv> <private-work-dir> <query>` + `CKC_BENCH_SINK=closed-file-v1`; typical command = `checker orchestrate --provider static`. It writes model/certificate/phase files, then `answers.txt` (all bytes written, flushed, file closed), then atomically renames `sink-complete.tmp` → `sink-complete.tsv`. Marker = LF lines `sb1-sink 1`, `closed_unix_ns<TAB>N`, `bytes<TAB>N`, `sha256<TAB>H`, `cpu_ticks<TAB>N` (own + waited child utime/stime). Byte count/hash bind the closed file. Marker time = same-host UNIX ns immediately after close, mapped through a controller monotonic bracket; clock discontinuities, out-of-owner timestamps, missing/invalid markers and mismatched bytes refuse a complete timing result. Calibration uncertainty is reported.
- The harness checks every required owner phase, kind and nonoverlapping offset against the pre-sink owner interval. `scored_ns = sink_end_ns − load_ns`; `wall_ns = load_ns + scored_ns + teardown_ns`. Teardown is one exclusive `lifecycle` ledger interval and a load-side row in `lifecycle-phases.tsv`; RSS and the operational deadline span it. Its CPU uses post-marker owner/waited-child ticks; parent stage CPU is conservatively assigned before the sink, later parent CPU to lifecycle. No concurrent child wall is added to its owner. Legacy separate commands retain whole-invocation-minus-load scoring for regression comparisons. `checker_rc` = combined owner rc; `producer_rc` blank in orchestrated mode.
- Outputs = `<out>/runs.tsv` (block/order, exclusive intervals, CPU, load/scored wall, `sink_end_ns`, `teardown_ns`, `sink_clock_uncertainty_ns`, summed peak RSS, per-lifetime high-water marks, outcome) + raw RSS series. `<run>/phases.tsv` appends `kind` to the existing phase columns. Answers publish only after a complete accepted run; malformed phase reports fail closed.
