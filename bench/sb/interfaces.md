# SB1 seams (MAIN; fixed before builders start; contract `sb`)

All text UTF-8, LF; ground terms in the canonical v1 writer's spelling (`ckc_kernel::contract` reader/writer; the fork's `render_term_line`).

## Composition (generator → producer, checker, harness)
- `<dir>/composition.tsv`: one path per line = load order (documents, then the patient world); a relative path resolves against the repository root every tool takes as an explicit argument (`--root`), never the working directory. `guidelines/schema.pl` is not listed (built-ins load engine-side) but is pinned by the identity below. Comment lines `#`.
- Composition identity = sha256 over the framed records `schema\0<len>\0<sha256(guidelines/schema.pl)>\n`, then per listed file in order `file\0<path as listed>\0<len>\0<sha256(bytes)>\n` (len = decimal byte count).
- `<dir>/manifest.tsv`: `key\tvalue` rows — family, scale point, G, k, transform version, generator commit, input sha256 per source document, seed, patient profile id, expected-output sha256 (q-all), annex param ids.
- `<dir>/queries/q-all.pl`, `q-one.pl`, `q-patient.pl`: frozen query files (q-all = the enumeration of `tests/consumer/driver.pl.in`; q-one + q-patient = committed `ckc v1` question files).

## Producer (`prototype/sb1/producer.pl`, SWI 10.0.2)
- `swipl -q -f none -F none -s prototype/sb1/producer.pl -g sb1_main -t 'halt(9)' -- <composition.tsv> <out-dir>`.
- Loads `guidelines/schema.pl` + the composition under the REFERENCE § Loading recipe (tabling), evaluates, writes `<out-dir>/model.txt` (every model fact incl. metadata facts, one per line, standard order of terms, deduplicated) + `<out-dir>/certificate.txt` + `<out-dir>/producer-phases.tsv` (`phase\tseconds\tcpu` rows: load, eval, certificate, write; immutable once written). Failure = rc ≠ 0 + one stderr line naming the stage (load | eval | certificate | write | resource).
- Certificate envelope: line 1 `sb1-certificate 0`; line 2 `composition <composition identity>`; then one line per model fact: `<fact>\t<clause-id>\t<valuation>\t<level>`; clause-id = `<document index>:<clause ordinal in that file, 1-based>` (patient facts included as documents); valuation = `[V1=T1,…]` over the clause's non-local variables in first-occurrence order; level = a natural number: facts of the composition (metadata + patient facts included) = 0; an instance without positive body facts ≥ 1; otherwise > every positive body fact's level.
- Level algorithm (D7): ground every clause body against the model (candidate instances, NAF + built-ins evaluated against the fixed model), then an agenda: facts of the composition start at 0; an instance becomes ready once all its positive body facts hold levels and gives its head 1 + max(those levels) (max of none = 0); the lowest ready level wins, so a founded support is chosen whenever one exists; facts left without a founded instance = an unfounded residual (reported; the run fails).

## Checker (`prototype/sb1/checker/`, Rust prototype)
- `checker --root <repo> <composition.tsv> <model.txt> <certificate.txt> [<query.pl>]` → rc 0 = accepted (stdout = the query's answers, or `accepted <n> facts`), rc 1 = refused (stderr one line: `refused <stage> <first failing claim>`, stage ∈ envelope | identity | claim | closure), rc 2 = usage / parse / I/O (stderr names it); writes `checker-phases.tsv` beside the model (`load` = parse of the composition, reported apart; `decode` = certificate + model parsing, charged; `admission`, `index`, `support`, `closure`, `answers`: seconds + CPU) + `checker-counters.tsv` (logical counters apart from runtime counters, contract D6). Levels: any natural numbers satisfying the strict decrease are accepted. `accepted` = a prototype test result, never the public claim of Decisions Patient answers.
- Checks: envelope + composition identity; every model fact claimed once; each claim's instance (clause head = fact under the valuation, built-ins hold, every NAF absent from the model with locals existential, positive body facts in the model with lower levels); closure over every enabled instance of every clause (T_M(M) ⊆ M); answers projected, canonically sorted + deduplicated.

## Harness (`ckc bench run`)
- `ckc bench run <composition-dir> --producer <cmd> --checker <cmd> --query <q> --blocks <n> --out <dir>`: spawns each phase as a subprocess under `heavy` (the reference protocol of D6), records the interval ledger, process-tree RSS samples, outcomes; writes `<out>/runs.tsv` (one row per run: block, order, phase intervals, CPU, peak summed RSS, per-process high-water marks, outcome) + raw RSS series.
