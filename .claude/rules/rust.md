# Rust + Verus law

- Toolchain = `just tools`: installs every sha256-pinned tool into `.toolchain/` (idempotent; `CKC_TOOLCHAIN` relocates) — rustup + the `rust/verus.lock` rustc toolchain (+clippy, rustfmt, `x86_64-unknown-linux-musl` target) + the Verus release asset + `rust/tools.lock` rows (just, verusfmt, cargo-deny, gitleaks, zizmor). `$T/<tool>/.pin` = the installed lock row's sha256; a differing lock row reinstalls. Symlinks land in `.toolchain/bin/`; `just` exports `RUSTUP_HOME`/`CARGO_HOME`/`PATH` itself. Direct rust Bash calls (outside `just`) still export `RUSTUP_HOME=$R/.toolchain/rustup CARGO_HOME=$R/.toolchain/cargo` + prepend `$R/.toolchain/verus-x86-linux:$R/.toolchain/cargo/bin` beside the swipl/python shims. Kani 0.67.0 = the secondary gate (`just kani`, bullet below).
- Gate = `just rust` = `fmt-check` → `clippy` → `verify` → `build` → `trust` → `test` → `deny` → `secrets` → `workflows`; each recipe prints `gate: <step> ok` except `trust`, whose green line is the `ckc: trust …` meter; `just gate` adds `just check` (`ops.md`) + `just certify` (M6: `ckc certify <id>` per guideline ≈ 9 min + `ckc certify --cases tests/certify/cases.tsv` ≈ 2 min; `CKC_BIN` names a prebuilt binary). CI `.github/workflows/ci.yml`: job `rust` = `just tools` + `just rust` + `just build-static` (toolchain cached on the lock hashes; uploads the static musl binary — the swipl:9.2.9 image = Debian glibc 2.36, the runner build needs 2.39), jobs `check` (`just check`; installs procps — `ckc check` kills timed-out process groups with /bin/kill, absent from the image) + `certify` (`just certify`, R83) in that container over the static binary; weekly jobs `advisories` (`just deny`), `kani` (`just kani`), `updates` (`just workflows` online with the job token + `just outdated`); `.github/dependabot.yml` = weekly github-actions PRs (7-day cooldown). Local container reproduction = `sudo podman run --rm -v <root>:/w:ro -w /w docker.io/library/swipl:9.2.9@sha256:3e4b85b1… ./rust/target/x86_64-unknown-linux-musl/release/ckc certify …`.
- Late `ckc check` mutants = `just late-mutants` (secondary, ~3 h: one full check per row): `tests/check-mutants/late.tsv` + `late/<name>.expect` = the 4 M5.3 mutants whose first violation lies after the SWI-Prolog stage (nonfinite-anchor, queries-fixture-pin, red-expect-altered, red-ace-compiles); pins = the legacy first violations with the R99 `goal:`→`ckc:` prefix.
- Kani secondary gate = `just kani` (~2.5 min + bootstrap): `rust/kani/bootstrap.sh` (digest-verified offline install from `rust/kani.lock` into `.toolchain/kani/`; cold 30 s, idempotent 1 s; `--env` prints the exports; `cargo-kani` executes only after `setup` has populated the exported `KANI_HOME` — any earlier run, `--version` included, self-installs an unpinned bundle into `~/.kani` ⇒ wrapper identity = `wrapper/.crates.toml`) → `rust/ckc-kani-harness/` (separate `[workspace]`, path dep on the kernel; harnesses `align_two_byte_domain`, `reader_v1_check_small`, `reader_v1_check_prefix_of_committed`, explicit `kani::assume` domains + `#[kani::unwind(N)]`). `engine_answer_tiny` + `reader_trace_check_small` stay in the crate OUTSIDE the recipe: CBMC cannot fold a read of an unequal-variant enum back from a heap `Vec` (Kani's buffers = untyped byte objects) ⇒ the kernel's arena/goal/body reads stay symbolic on concrete input + every data-dependent loop unwinds to its bound (one concrete `unify` rc124 at 600 s; whole-file `v1_answer` 5 runs rc124 at 1200 s / ~12 GiB). Re-open trigger = a `rust/kani.lock` bump → rerun `engine_answer_tiny` ≤1200 s (`.agent/deferred.md` row). Kani bumps = edit `rust/kani.lock` (asset sha256s + vendor_crate rows) → `just kani`.
- `verify` recipe = `cargo verus verify -p ckc-spec --locked --offline` (warms vstd plain — vstd axiomatizes std and cannot pass `--no-cheating`; a cold `--no-cheating` run fails on vstd) → `cargo clean -p ckc-spec -p ckc-kernel` (results are content-hash cached and cargo skips unchanged crates whatever the verifier flag) → `cargo verus verify --workspace --locked --offline -- --no-cheating` (never `focus`; the flag rejects assume/admit/external_body/assume_specification/assume_termination). ~5 min warm. A `&mut` reference inside a big loop invariant can kill Z3 outright — `expected rlimit-count in smt statistics` = solver death; remedy = per-iteration local + hide the expansion in the caller, never a bigger rlimit. A timeout/rlimit change = a proof change, never a retry.
- Format = `verusfmt --edition 2024` (`just fmt` writes, `fmt-check` gates; rustfmt runs outside `verus!` blocks). verusfmt 0.7.2 lexer quirks: a string literal ending in an escaped backslash reads as unterminated → spell that backslash `\u{5C}`; block-form `ensures {…},` fails to parse → `ensures ({…}),`.
- Lint = `cargo clippy --workspace --all-targets -- -D warnings`. Kernel-wide allows live in the `ckc-kernel/src/lib.rs` header (ghost-erasure families: unused/dead; proof-shape families: `ptr_arg`, `len_zero`, `question_mark`, `single_match`, …); a new lint class in uninspected code → extend that header, never inline `#[allow]` sprinkles. `ckc-spec` allows `unused_imports` only; `ckc` (shell) carries no allows. `[workspace.lints.rust] unexpected_cfgs` declares the `verus_keep_ghost*`/`verus_verify_core` cfgs.
- Dependency policy: `rust/deny.toml` (advisories; licenses `Apache-2.0 | Apache-2.0 WITH LLVM-exception | MIT | Unicode-3.0`; multiple-versions + wildcards + unknown sources denied; crates `publish = false`). Update notice = `just outdated` (weekly CI `updates` job; bash + curl + jq): every `Cargo.lock` crate (both workspaces) vs crates.io newest stable, `tools.lock` rows + rustup vs upstream latest, `verus.lock` release vs latest Verus release (rustc, Z3, `vstd`/`verus_*` crates follow it, reported only), `kani.lock` Kani vs latest; rc 1 = drift, rc 2 = a failed or empty upstream answer; swipl container digest = deliberate reference-runtime hold, outside the check. Bump procedure: `cargo update -p <crate> --precise <v>` → `cargo vendor` → `rust/target/release/ckc trust-audit --write rust` (deps-allowlist + spec-manifest regen) → `just rust` green → commit. Verus/Kani/tool bumps = edit `verus.lock`/`tools.lock`/`kani.lock` (asset sha256 from the release checksums) → `just tools` (pin binding reinstalls) → `just rust`.
- Secret scan = gitleaks 8.30.1 with `.gitleaks.toml` (default rules; path allowlist = `rust/vendor/*/.cargo-checksum.json` digests); `just secrets` = full history + `--pre-commit` (unstaged) + `--staged`.
- Workflow scan = zizmor 1.30.1, regular persona: `just workflows` = offline audits over `.github/` (workflows + dependabot.yml); `GH_TOKEN` set ⇒ online audits too (weekly `updates` job). Fix findings in the workflow; an inline `# zizmor: ignore[<audit>]` carries its reason on the same line.
- Workspace: `ckc-spec` (trusted, MAIN-authored, human-read) + `ckc-kernel` (impl+proofs, AI-authored + never human-reviewed; agents read + edit it; the verifier + gates = its whole review) + `ckc` (unverified std+sha2 shell). Committed `Cargo.lock` + `rust/vendor/` + `.cargo/config.toml` vendored-sources; deps grow only via `rust/trust/deps-allowlist.tsv` (no-default-features closures, no proc-macros in kernel).

Accepted residual = comment-split INCLUSION vectors only. Green meter `ckc: trust spec=<lines> shell=<files> assumes=<sites> deps=ok`. Allowlist+manifest regen after any trusted-surface edit (incl. `just fmt` over spec files) = `rust/target/release/ckc trust-audit --write rust` (explicit rebaseline: deps rows from Cargo.lock, every scanner hit adopted as an escape row, spec-manifest re-pinned, then the read-only audit sets the rc; never inside a gate recipe — the adopted rows are the diff to review).
