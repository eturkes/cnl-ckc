# Project operations

- Toolchain (dev machines): a system swipl ≠ 10.0.2 → `just swipl` (idempotent, digest-verified source build) = gitignored `.toolchain/swipl-10.0.2/` + `bin/` shims `swipl`→that prefix, `python3`→uv cpython 3.15 where uv supplies it (scratch + archived migration scripts only). EVERY Bash call: `export PATH="$ROOT/.toolchain/bin:$PATH"` (shell state resets per call); a PATH without the shim leaks system swipl into `ckc` → `ckc: swipl-version: expected 10.0.2, found: …` rc=2 = toolchain leak, not a corpus defect. CI digest-pinned swipl:10.0.2 container = reference runtime.
- Rust tooling = `just tools` (sha256-pinned installs into `.toolchain/`; `rust/verus.lock` + `rust/tools.lock`); direct rust Bash calls (outside `just`) add the `rust.md` exports in the same call; gate + workspace law → `.claude/rules/rust.md` (fires on `rust/**` + `justfile` touch).
- Deterministic SWI: always `-f none -F none`; writer options explicit.
- Standing decisive chain = `just gate` (root `justfile`; `.toolchain/bin` on PATH) = `just rust` + `just mobile` + `just check` + `just certify` (steps = spec `Artifacts` Gates; rust chain law = `rust.md`); each step prints its green line — `gate: <step> ok`; `fmt-check`: `gate: fmt ok`; `trust`: the `ckc: trust …` meter; `check`: `spec-lint: ok` first (firing = `spec-lint.md`) — then `time: <step> ok|red <s> s` + its step-ledger row (Step ledger bullet) (`test`: every binary runs (`--no-fail-fast`), totals + its 5 slowest binaries; a failing run adds each failed binary, each binary without a result line + cargo's error lines, log = `rust/target/test.log`), the run `time: total ok|red <s> s`; the full gate runs once per unit, on its commit, in the background (`just ci <unit>`, else the pool form of `CLAUDE.local.md`), MAIN working on meanwhile; the next commit waits for its verdict, red → fix + amend while that commit is HEAD; a host without the gitignored toolchain bootstraps in the same command = `just tools && just gate` (+ `just swipl` where SWI-Prolog 10.0.2 is absent). Fast gate (iteration; latency-bounded; `just gate` closes the unit) = the steps + tests the change reaches, independent ones in parallel shells (cargo steps share one target lock): `rust/**` → `just fmt-check clippy build trust` + each touched area's harness `cargo test --test <name>` (exports + harness map = `rust.md`) + once `ckc-spec` | `ckc-kernel` change, per touched module + each module calling a changed spec fn: `cargo verus focus -p <crate> --locked --offline -- --no-cheating --verify-module <module>` from `rust/` (rust.md exports; `k4_bytes` 89 s) — `just verify` (canary + `cargo clean` of both crates = a cold re-verify, ≈ 18 min) stays in the full gate + the corpus step a touched command drives (`ckc check` | `ckc ui check` | `ckc certify <id>`); `guidelines/<id>/**` → `ckc compile <id>` + `ckc queries <id>` + `ckc check` + `cargo test --test consumer_recipe` + `cargo test --test sgw_acceptance` (its P2 grades every committed document's spelling); `vendor/**` → `just check` + `just certify`; UI markup, style or script (`rust/ckc/src/ui/**`, `rust/ckc-spec/src/ui.rs`, `tools/ui-mobile-probe.mjs`, `tools/ui-reading-probe.mjs`, `tests/ur-ui/browser/**`) → `just mobile` too; `.agent/spec.md` → `.agent/spec-lint`; `justfile` → the recipes it touches; `.github/**` → `just workflows`. `ckc check` stops at its first violation and verifies release-manifest freshness before its SWI-Prolog stage; per guideline the vocabulary table grammar runs first (a table defect stops the run before the lexicon's full Clex pass, ~60 % of a pre-SWI run); per-item SWI work (`ckc check` documents, red + green probes, questions; `ckc compile` documents; `ckc queries` questions) runs on `CKC_JOBS` workers (default = available parallelism, `1` = sequential) and reports the failure a sequential run reports first (`check/par.rs`); the manifest = HEAD content digests only (no commit id) ⇒ a commit touching release inputs (guidelines/, the fork, clex, NOTICE, LICENSE, the REFERENCE schema section) carries its own manifest: commit, then `just amend-manifest`; - CI gate (`CLAUDE.md` `Execution`) = `just ci <unit>` (unit names: main = the unit id (`qlf`, `id2`, …), a release line = `kb-<date>-<topic>` ⇒ main + line runs never share a `ci/` branch): a clean tree's HEAD → `ci/<unit>` → the `.github/workflows/ci.yml` run on that commit (push trigger `main` + `ci/**`): job `rust` (`just tools`, `just swipl`, `just rust`, `just mobile`, static `ckc`) → `check` (`just check`) ∥ `certify` (`just certify`) over that binary in the pinned swipl container = every `just gate` step, graded on the commit (HEAD-cloning + history-reading checks included); prints the run id, commit, tree + `time: <job> <conclusion> <s> s` + one `ci:<job>` step-ledger row per graded job; green → deletes the branch, `gate: ci ok`; red → `--log-failed` tail, branch kept: fix, amend, rerun. ≈ 75 min (rust job ≈ 50) → background to a log. A message-only amend after the run keeps the graded tree (`git rev-parse HEAD^{tree}` equal) = the commit's gate record. `just gate` = the same chain on this host: iteration's full run + the fallback where CI cannot run.
- Step ledger (`CLAUDE.md` `Execution` Gate command + Gate usefulness) = `<git-common-dir>/ckc-gate-ledger.tsv` (`CKC_GATE_LEDGER` overrides) in place of the template's gitignored file: one record per clone, shared by its linked worktrees, kept through worktree removal + `git clean`, outside every status check. Rows = date, tree (the working tree's own id; `HEAD^{tree}` when clean), step, seconds, verdict `ok|red`, class, note: one per step of a `_timed` run (`just gate`, `just rust`) + one per job of a `just ci` run (`ci:<job>`); fast-gate commands append none (an iteration red = the TDD signal). Each row also prints as `gate-ledger<TAB><row>` ⇒ a pool run's rows, whose ledger stays on the pool host, come home by `just ledger-import <log>` (keyed on date + tree + step; a rerun appends nothing). A red row enters `unclassified`; classify it on the spot: `just ledger-classify <line> <product|gate|flake|planted> <note>`; a rerun's verdict counts once that red is classified; `gate` + `flake` = a gate bug → a `.agent/deferred.md` row, its fix the next unit. `just ledger` = the unclassified reds + per step: runs, seconds, reds by class + `sole` (product reds alone in their run). `_timed` stops at the first red, because a later step would grade a stale `ckc` binary ⇒ a step's record counts what the steps before it missed. Campaign tier = the weekly ci.yml jobs (`advisories`, `kani`, `updates`) + the manual + `#[ignore]`d tiers (`just late-mutants`, `just mutants`, ID2 P5–P7, the `cix2_tests` scaling probes) + time-boxed runs at a unit's or phase's close; each finding there → a pinned example in the per-commit gate. Checks = `recipes.rs` (`rust.md`).
- Release lines (procedure = `docs/REFERENCE.md` § Releasing; rulings = spec Decisions `Publication scope`): `main` = development; a cut = branch `release/kb-<date>` + SSH-signed annotated `kb-<date>-rc.<n>` (signer = `CLAUDE.local.md`; verify each tag + its files per § Releasing before the user's push) + the review worktree `.release/kb-<date>/` (gitignored, durable: it holds the reviewer's live ledger, so task-close cleanup leaves it; its recipes export `CKC_TOOLCHAIN=$ROOT/.toolchain`). Line commits land on `release/kb-<date>` in that worktree, whichever branch the session starts on (ruling on `CLAUDE.md` `Execution` Git "commits land on the branch the session starts on"; user rulings: spec Decisions `Publication scope`, Tasks PR8). The line takes only ledger batches (MAIN commits them on the user's request, then `just amend-manifest` in the worktree), corrections of rejected documents (a corpus round run in the worktree, committed on the branch), development-tooling + operating-procedure changes that leave every release input unchanged (template refreshes, gates, agent law; on the user's request; user ruling at the template-refresh request) and the release record; the line's `.agent/spec.md` + `.agent/deferred.md` stay as cut (the live state = main's; a line commit leaves them alone, so the merge keeps main's side instead of re-adding rows main has since dropped); the template copies (`CLAUDE.md`, `.claude/agents/`, `.agent/spec-lint`) take main's side at the merge too — the line takes only refreshes main already took, so the line lands merged onto main's refresh, never as an exact-tree copy; `just ci <unit>` from the worktree grades the line; tags, branch pushes + GitHub releases = remote actions on the user's go. After the release tag: the merge = REFERENCE § Releasing step 14 (contract `mrg`): compiled products, review + release manifests keep neither side's bytes — main's `ckc` recompiles every touched guideline (the line stays at its cut's identifier, main can carry a later one); an ACE conflict = the user's ruling, recorded in the merge message; commit, `just amend-manifest` (amends the merge, both parents kept), `ckc certify` + `ckc check`, gate, then `git worktree remove .release/kb-<date>`; rehearsal = `python3 -I .agent/archive/rehearsals/release-merge.py <repo-root>` (disposable clone, ≈ 25 min; rerun after each schema-meaning unit, e.g. DC). The line's runs share main's `.toolchain/` while their pins agree; a tool pin bump on main while a line is open first gives the line its own store (`CKC_TOOLCHAIN=<line worktree>/.toolchain`, `just tools` there). The cut freezes the line's schema identifier: the next predicate-set or meaning change on `main` = the next identifier (spec Decisions `Schema evolution`).
