# Reviewer-UI law

Live law = docs/REFERENCE.md § Reviewer interface + `.claude/rules/clinician-design.md` + the K5 spec `rust/ckc-spec/src/ui.rs` (render fidelity, escaping, copy registry, session gate + POST guard chain + ledger CAS; theorems in `ckc-kernel` `k5_*`). Contracts of record: `.agent/archive/contracts/m5u5*.md` (R84 guard order).

- `ckc ui serve|render|check|request|copy-check` (`rust/ckc/src/ui/`): std `TcpListener` on 127.0.0.1 only, per-process 64-hex form token + 64-hex launch session (Session bullet); every page byte comes from the kernel renderer; `check` = double-render byte compare + page invariants + dangling-href closure; `request` = one in-process request (fixture + oracle seam).
- Committed-corpus law: the reviewer surface reads HEAD, never the working tree (`corpus.rs`): `git archive HEAD guidelines` → temp tree, live ledgers overlaid; filesystem mode only when git is unusable ∨ root ≠ toplevel. Ledger CAS + write target the working tree. `ckc check` + `ckc ui check` read the working tree (pre-commit gates). The law stays invisible in copy (user ruling); fixture carriers = `tests/ui/green/git-{uncommitted-edit,untracked-document}` (`worktree/` beside `tree/`: `ui_fixtures.rs` commits `tree/` as HEAD with fixed identities + dates, lays `worktree/` on top uncommitted ⇒ fixture commit ids are functions of fixture bytes).
- Session (contract `.agent/archive/contracts/sec7.md`, user ruling R1 of `.agent/archive/contracts/sec.md`: clinicians never see, copy or launch a secret): `ckc ui serve` draws a per-launch session (32 urandom bytes hex, ≠ token), writes the kernel's `ui_signin_page` (meta refresh → `/session/<session>`) to `$XDG_RUNTIME_DIR/ckc-ui-<port>.html` when that dir is ours + 0700, else a 0700 temp dir, file 0600, and runs the opener on that path (`$BROWSER` first `:` entry | `xdg-open` with `DISPLAY`/`WAYLAND_DISPLAY` | `wslview` with `WSL_DISTRO_NAME`) — the secret never reaches an argv or the terminal while a browser opens; no opener → stdout `ui: no browser opened. Open this address: …`; each stdin line (Enter) reruns it (stdin at EOF — no terminal, `/dev/null` — leaves no way to reopen). Kernel `gate(req, port, session)` (spec ui.rs, read first by `post_outcome`): Host 403 → GET `/session/<session>` 303 `Location: /` + `Set-Cookie: ckc-session-<port>=<session>; HttpOnly; SameSite=Lax; Path=/` (Lax: the first navigation comes from a `file:` page, cross-site, and Strict withholds the cookie on its redirect) → method 405 → no `;`-pair `ckc-session-<port>=<session>` → 403 `Open the review site from ckc`. The shell calls `ui_gate` before any body read (serve.rs) and before any snapshot (`request::respond`); a body is read only past the gate ∧ `may_read`, ≤ 64 KiB; 10 s to read the request, a fresh 10 s to write the answer, then a lingering close (half-close + ≤ 128 KiB / 1 s drain: an unread refused body otherwise resets the answer away; `ui_socket.rs` `refused_body_still_gets_the_whole_answer`); each connection runs on its own thread with a 64 MiB stack (a page load's snapshot alignment check recurses once per table character, `ckc_kernel::align_impl::split_at_seps`: the CDC 13.7K-character table needs ~2.25 MiB, past a spawned thread's 2 MiB default; `a_long_alignment_table_loads_on_a_connection_thread`: a 40,000-character table, red on the default stack = abort), ≤ 32 at a time (a slot = a sync-channel token, freed on drop, also while a panic unwinds; past the cap, newcomers wait in the listen backlog), so stalled clients hold slots, never the loop (`stalled_clients_leave_a_request_answered_at_once`: 8 clients stalled mid-request, a signed-in page answered < 1 s; firing: the single-threaded loop → no answer within 3 s); concurrent ledger writes serialize on `LedgerLock` (`File::lock` = flock, per open file ⇒ it excludes threads of one process too). `ui request` seam: `--session <64 hex>` + `--header Cookie:…`; without `--session` the session steps stay off (fixtures unchanged). Residual (documented): a 127.0.0.1 cookie goes to every port ⇒ another account whose local page the reviewer opens can capture it. Tests: `ui_socket.rs` (sign-in, refusals, opener argv + modes + Enter, body cap, deadline, gate-before-snapshot via `ui request`), `ui_commit.rs` servers sign in from the printed address. Usage re-pin = `.agent/archive/migrations/sec7-usage-repin.py <repo-root>`.
- Rendered commit (review custody): document pages carry hidden `commit` = the snapshot commit (git HEAD | `ui request --commit` | empty in filesystem mode); POST: the kernel parses `commit` (empty | 40 lowercase hex) and the shell reads it only through `ui_posted_commit`; the shell attests `at_commit` = (posted commit, bundle v2 review digest of the docid there) after `cat-file -e <c>^{commit}` + `merge-base --is-ancestor <c> <snapshot>` + an archive-at-commit derivation (posted = snapshot → the HEAD derivation); kernel guard = (snapshot empty ∧ posted empty) ∨ attestation == (posted commit, posted digest), else 409; the row records the posted commit.
